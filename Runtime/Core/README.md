# Pure C# raster reference core

This folder targets C# 8 / Unity 2022.3-compatible `System` APIs. It has no UnityEngine dependency.

## Coordinates and storage

- Pixel `(0, 0)` is the bottom-left pixel; its center is `(0.5, 0.5)`.
- Layers are ordered bottom-to-top. Tile and full-frame buffers are row-major RGBA8, lowest Y first.
- Alpha is straight/unassociated coverage. RGB is stored as supplied; this proof does not perform ICC conversion or linear-light color management.
- Missing tiles are zero RGBA. Uniform tiles retain one RGBA value. Other tiles use full fixed-size buffers. Edge padding must remain zero.
- Zero-alpha RGB imported from files is retained exactly. Explicit complete erasure clears RGB as well as alpha.
- Tile exports are detached copies; import copies caller memory. Internal transaction snapshots are copy-on-write, never brush replay.

## Painting and history

`PaintDocument.BeginStroke(layerId, channel, settings)` freezes settings. Feed pixel-space `BrushSample` values with nondecreasing times using `Add`. The stroke samples arc length at a fixed fraction of the nominal brush diameter; pressure is linearly interpolated at each stamp. Duplicate positions create no extra stamps. There is no forced second endpoint stamp on commit. Pressure has independent linear size, opacity and flow assignments.

For mesh-derived dabs, `ApplyPixel(x, y, coverage, pressure)` accepts already-computed geometric coverage. Union duplicate triangle coverage for each dab before calling. PressureSize is not applied here because the caller already chose the footprint. `BeginStroke` paints one channel; `BeginMaterialStroke(layerId, channels, settings)` paints several channels of a paint layer in one transaction (Substance Painter's material painting): each `ChannelPaint` gives a channel and the value laid there (the brush colour of a one-channel stroke). The stroke keeps one per-pixel coverage (dabs, dual brush, texture, stabilizer, tapers, curve, selection) and, per channel, its own rollback copies, colour and colour-dynamics stream seeded as a stroke of that channel alone, so every channel ends byte-identical to `BeginStroke` on it with that value (tests compare them, including worker-thread dabs, selections and mesh dabs). Lock Transparent Pixels is decided per channel and pixel; erase erases every listed channel. Channels switched off on the layer are switched on when the stroke begins and are part of its single undo step (the surface objects are kept across undo/redo); a cancel, an exception or a commit that changed nothing switches them off again. The shared coverage and every channel's copies count together against `ActiveStrokeBudgetBytes` (wash 64 + tile² × 4 bytes per tile once, plus each channel's copied tile and, with per-tip colours, tile² × 16 bytes).

`PaintDocument.BeginTriangleFill(layerId, channel, color, opacity, erase)` / `BeginMaskTriangleFill(layerId, amount, reveal)` start a `TriangleFill` (the polygon fill's drag): `Add(triangles)` (canvas pixel coordinates) grows the filled union, and the pixels always equal `Fill` / `FillMask` of `SelectionMask.FromTriangles(union)` within the selection the fill began with, whatever the order or grouping of the adds (each pixel keeps the union of its 4×4 sample bits; a changed pixel is recomputed from its value before the fill with the same pixel rule as Fill). It is carried by an ordinary `BrushStroke` (`Stroke`), so it blocks other edits, commits as one undo step and cancels back exactly; invalid coordinates and budgets cancel it. Sample masks count in `ActiveStrokeBudgetBytes` like the brush's scratch (fully covered tiles keep none). The rasterizer (`TriangleSamples`) is shared with `FromTriangles`; per pixel it tests the corners of the sample hull against each edge with a margin of 1e-12·(M+1)² (M: the largest coordinate), 100× the double-precision error bound of the edge function, so it skips per-sample tests only where they cannot differ (bit-identical to the per-sample raster, tested against a frozen copy), and works tile by tile in parallel. Whole-tile edits apply to a one-channel or mask stroke only; a material stroke refuses them.

`Commit()` stores exact changed-tile before/after states (for a material stroke, of every channel, undone and redone together after one source-budget check of their total growth). `Cancel()` and `Dispose()` restore the original state. Invalid input and budget errors during Add/ApplyPixel automatically cancel. No-op commits retain redo. Undo/redo cannot interleave an active stroke. Layer structure/metadata changes use the same bounded history.

Direct `SparseTileSurface.SetPixel`, `ImportTile` and `Clear` are import/administrative mutations, intentionally clearing document history. Call `ClearHistory` after constructing an imported document. `GetChannel` creates an absent empty enabled channel; `TryGetChannel` is the side-effect-free query. A disabled existing channel remains disabled and its pixels are retained.

## Memory contracts

`SourceBudgetBytes` defaults to 256 MiB; `ActiveStrokeBudgetBytes` defaults to 64 MiB; undo/redo payload defaults to 64 MiB. Tile expansion, rollback capture and undo restoration preflight their budgets. Refused strokes restore previous pixels rather than retrying allocations. `HistoryTrimming` fires before dropping exact old commands, reporting the number of payload bytes discarded.

Counters account for pixel payload and nominal history headers, not managed object overhead, uploaded GPU textures or external codec buffers. `PeakWorkingBytes` is a conservative current payload estimate, not a measured application-memory peak. These limits do not promise the full specification's 100-layer 4K workload fits in memory. Single-threaded access is required; readers must not race mutation. Serialization should reject active strokes or explicitly finish them first. `SparseTileSurface.AllocatedBytes` is a running total kept by every tile change (budget checks do not walk the tiles).

## Threads

The document is single-threaded for its callers, but several operations use worker threads internally and return only after they finish: `CpuCompositor.CompositeRegion` / `CompositeRegions` (and `Composite`), `NormalMaps.Output`, `Fill` / `FillMask` / `Gradient` / `ReplacePixels`, `TriangleFill.Add` and `SelectionMask.FromTriangles` (tile by tile), `Transform`, `Resampled`, the magic wand, selection builders and edits, filter evaluation, and brush dabs whose bounding box has at least 128 × 128 pixels. `CoreParallelism.MaxDegreeOfParallelism` caps them (0 = one per processor, 1 = everything on the calling thread). Every output pixel is computed from its own inputs, so the bytes do not depend on the number of threads (tests compare 1, 2, 3 and the default). Workers only read the document and write their own output slots; everything that allocates tiles, checks a budget, records history or touches the filter cache stays on the calling thread, in the same order as a sequential run, so a refused or failing operation leaves exactly what the sequential code left. Brush strokes notify the surface's revision and change journal once per tile per dab rather than per pixel; which tiles are reported is unchanged, the revision numbers themselves are not part of the result. The GPU compositor, mesh baking (its own `MeshBakeBudget`) and PSD/persistence code are outside this setting.

## Canvas size

`PaintDocument.Resampled(width, height, resampling, sourceBudgetBytes)` returns a new document at another size (1..8192 per side, `MaxNativeSide`, the largest the native archive reads back) and never changes the original: the same document and layer IDs, structure, attributes and settings, no history, a `Revision` that continues after the original's. Raster channels, masks and the selection are resampled with `CanvasResampling` (Nearest copies the pixel under the new centre; Bilinear weighs the four around it; Area averages the covered source area with exact fractional overlaps). Weights come from integer arithmetic, the canvas edge repeats outside, averages are premultiplied, a pixel read only from equal pixels is that pixel, a pixel that comes out fully transparent keeps the plain average colour of the transparent pixels it covers (so the RGB stored under zero alpha survives), and averaged Normal pixels are renormalized. Values measured in pixels follow the scale (geometric mean of the two axes): blur and sharpen radii (rounded half away from zero, 1..the filter's maximum), the Height → Normal strength (±256), 2D paths (points and brush radius, drawn again from the scaled path). Clamped values are reported in `Notes`; layers with a path on the model keep their UV-bound path, get resampled pixels and are listed for the caller to redraw. Layer pixels are checked against the given budget tile by tile; going over throws and nothing is kept. Target tiles are computed in parallel (each from the source only) and stored in order, so the bytes do not depend on the number of threads.

## Project resources (`Shelf`)

`ImageContent` is an immutable straight RGBA8 image (bottom-left origin, 1–8192 per side) named by `ComputeHash`: SHA-256 of `YLPRGBA8`, width and height (32-bit little-endian) and the pixel rows bottom-up, so equal pixels have equal hashes whatever file they came from. `RgbaPng` writes it as colour type 6, 8-bit, non-interlaced, one adaptive filter per row, zlib, no ancillary chunks (deterministic bytes for one runtime's deflate), and reads only 8-bit grey, grey + alpha, RGB and RGBA without interlace, checking every CRC, the zlib header, Adler-32 and the declared size before allocating (palette, 16-bit and interlaced files are refused with a reason; the editor decodes those with Unity). The RGB under zero alpha survives both ways.

`ProjectResources` holds the resources of a project: `Add` returns the resource already holding equal pixels instead of a second copy, `Restore` keeps the IDs of a saved file, `ReplaceContent` swaps pixels under the same ID (`Revision` counts it), `Remove` asks the usage probes. `BudgetBytes` counts each distinct content once; `ResourceRefusedException` (TooLarge, OverBudget, TooMany, InUse, Unknown, Unsupported) leaves everything as it was. Every change raises `Changed` and bumps `Revision` (`IImageResources` is the read side for consumers). `ImageResampling` resamples a whole image with the canvas resampler's weights and per-pixel rule (byte-equal to resizing a document holding it); `BuiltInImages` makes the built-in images with integer arithmetic only (the tests pin their hashes). Persistence is `Persistence.ResourceIndex` (resources.json, the PNG entries, loading with verification).

Smart materials and smart masks (`SmartMaterial`, `SmartResource`, `BuiltInSmartMaterials`, `SmartPreview`; capture and placement in `PaintDocument.SmartMaterials.cs`; the file in `Persistence.SmartMaterialFile`): a fragment document holding the chosen layers (or one mask) at the size it was saved at, placed as one undo step with new IDs, resampled by `Resampled` for another size or tile size, unused channels switched off with their values kept, pinned generators pinned again to the maps where it is placed, refused before anything changes over the layer pixel budget, the layer limit (`MaxLayers`, the native reader's) or a filter budget. `ProjectResources.Smart` holds them next to the images (same count and budget; the file bytes and the fragment's pixels are counted).

## Fill images and projection

A fill layer's channel can read a project image instead of its one value (`PaintDocument.SetFillImage(layer, channel, resourceId)`, `PaintLayer.FillImages`); the value stays as what the channel shows where the image cannot be used. The layer's `FillProjection` (`SetFillProjection`, coalescing for drags) lays every image of the layer onto the texture set: Uv (the pixel centre in the UV square), Planar, Spherical, Cylindrical and Triplanar (the texel's point on the model from the baked Position map, through the model root's frame like the shape gradient, into the placement box's space; triplanar mixes three planar faces by the baked world normal and `BlendWidth`), then the UV transform (rotation about the centre, tiles, offset) and Repeat or Clamp. The formulas are in the type's summary. The document looks the IDs up through `ImageResources` (an `IImageResources`, set by the editor; not history or persistence) and resolves them again when its `Revision` changes, marking the layers whose image, colour space or presence changed; an ID it cannot resolve shows the value with a reason (`GetFillImageStatus`, `InactiveFillImages`, `MissingFillImages`) and is kept. `LayersUsingResource` answers the resources' usage probe.

Values (`FillImageColor`): data channels use the stored values whatever the image's colour space (as Substance Painter does); colour channels encode a linear (data) image to sRGB; scalar channels take the integer Rec. 709 luminance (grey unchanged); alpha is never converted. Sampling (`FillImageSampler`): a mipmap per content, conversion and luminance (`ImageMipChain`: each level halves the one before, area average over premultiplied alpha with the resampler's rules, levels ≥ 1 kept under `FillImageCacheBudgetBytes`, level 0 read from the resource through a table), bilinear at level 0 and trilinear when the pixel's footprint (from the UV transform, or from the nearer neighbouring texel's point on the model) is larger than a texel. A pixel read only from equal texels is that texel and a result whose alpha rounds to 0 keeps the transparent texels' average colour, so an exact Uv placement reproduces the image byte for byte.

Decals (`FillProjectionMode.Decal`, native version 17): a fill layer whose projection is a planar projection cropped to its placement box, faded or cut by depth (`DepthHardness`) and by faces turned away from the image's side (`BackfaceAngle`, `BackfaceHardness`; the baked world normal), and transparent everywhere else; `FillProjection.DecalAt(placement)` starts one with the image shown once (`FillWrap.None`: transparent outside the image's square, usable by every projection). Every channel with a value is evaluated (`PaintLayer.IsDecal`), not only the image channels: the decal's shape is the alpha of its first image in channel order (Color first), and each channel's own alpha (its image's, or its value's) is multiplied by that shape and the coverage and rounded once. A decal that cannot be placed (a map missing, stale or of another size, the model root not known) is transparent in every channel, never its value spread over the texture set (`GetDecalProblem`, `InactiveFillImages`); merging it is refused. Its tiles are skipped where the placement box cannot reach (`PositionTileBounds`: the box of every tile's baked positions, made once per Position map), and moving a decal (`SetFillProjection` from a decal to a decal, without filters) reports only the tiles either placement may cover as changed. `DecalCoverage` gives the reach on a grid for the editor's 2D view.

Image channels are evaluated like filter output (`PaintLayer.HasEvaluatedOutput`): the filter engine evaluates them block by block (stamped with the layer's `FillRevision`, and the maps' revision for the model projections), caches the tiles, and the compositors read `CopyOutputTile` (the GPU path uploads them). A request evaluates the stale blocks nearest to it, at most twice the worker count at once, so the display's time-sliced compositing can stop between blocks. Each pixel depends only on its inputs, so the bytes do not depend on threads, block or tile size. Native version 16 stores the IDs and the projection (`DocumentBinary`); duplicating, resizing and merging keep or rasterize them; PSD export writes a projected channel as a raster layer and reports `NotCarriedIntoExport` (`PsdBridge.Export(document, channel, notes)`; the overload without notes refuses).

## Layer operations

`PaintDocument.LayerOps.cs` and `PaintDocument.Merge.cs`. Each change is one undo step and changes nothing when refused (`LayerOpException` with a `LayerOpRefusal`).

- `DuplicateLayer` copies a layer — a group with its contents — with every attribute, its mask and effect stacks and its path, under new layer, effect and path IDs, directly above the original. Tiles are shared copy-on-write but count in full against `SourceBudgetBytes`.
- `MergeDown` / `MergeGroup` / `MergeVisible` build the merged layer off the document (a clipped layer is applied to its clipping base as the compositor clips it; a merge down otherwise lays the upper layer over the lower layer's own pixels and keeps the lower layer's mode, opacity and mask, or, at the bottom of an isolated stack with a lower layer that is not plain, composites both from transparent into a plain layer; a group is its contents composited from transparent; merge visible is the composite), swap it in for the merged layers, and composite every affected channel before and after with `CpuCompositor` (the swap is undone and redone around chunks of at most 16 MiB). Pixels transparent both before and after count as equal. When the visible difference (alpha, and colour × alpha) exceeds the tolerance (default 2 levels, the rounding of compositing two layers in another order) the swap is undone and `LayerMergeException` carries the `LayerMergeReport`; otherwise the report gives the counts. A merged pixel that comes out fully transparent keeps the lower layer's stored RGB where that is transparent too. Filters and generators are baked (a generator without usable maps refuses), paths become pixels. The merged pixels are computed tile by tile (in parallel under `CoreParallelism`, each pixel from its own inputs, so the bytes do not depend on the thread count) from the layers' output tiles with the per-pixel formulas the compositor uses (`CpuCompositor.BlendUnchecked` / `ClipOnto` / `Fade`, `NormalMaps`, `AdjustmentSettings.Composite`) and its tile presence rules; the comparison afterwards uses the compositor itself, so a difference between the two shows up in the report instead of being trusted. The merged layer's tiles count against `ActiveStrokeBudgetBytes`.
- `CopyPixels` / `CopyMerged` / `CutPixels` give a `PixelClipboard` (straight RGBA8 rectangle with its place in a document of the recorded size): the selection's amount fades pixels towards transparent premultiplied (fully selected pixels are copied exactly, RGB under zero alpha included), a mask copies as opaque grey (white shows), and the rectangle is trimmed to pixels with any value and refused above `maxBytes`. `PasteAsLayer` adds a paint layer in one channel, at the same place in a document of the same size or centred otherwise (pixels outside are cut off and counted), and deselects, in one undo step.
- Several layers at once (`PaintDocument.MultiLayer.cs`; a multiple selection in the Layers panel): `TopmostOf` drops layers inside a chosen group (they go with it); `RemoveLayers`, `DuplicateLayers` (source budget for all copies together), `SetLayersVisibility`, `MoveLayers` (into a group at a position among its other children, keeping the order), `StepLayers` (each one step up or down among its siblings, held back at the edge or by a chosen layer that stays), `TransformLayers` (every paint layer among them and in chosen groups with one `Affine2D`, the selection moved once, the undo data of all of them held to `ActiveStrokeBudgetBytes` together) and `MergeLayers` (siblings composited from transparent as an isolated group into a Normal layer at the topmost one's place, clipped when all are clipped to one base; compared like the other merges, including the layers between them whose clipping base changes). Each is one undo step and changes nothing when refused or failed.
- Per-channel blend settings (`PaintDocument.ChannelBlend.cs`, `ChannelBlend`, native version 14): `SetChannelBlend` / `SetChannelBlendMode` / `SetChannelOpacity` give a layer its own blend mode and/or opacity in one channel (a null part follows the layer; replace, not multiply), one undo step each (slider drags coalesce), refused under Lock All like the layer's own, marking only that channel in the change journal. `PaintLayer.BlendModeIn` / `OpacityIn` give the value a channel composites with. Duplicates, merges down (the lower layer's settings), merged groups (pass through becomes Normal) and resampling keep them; the merge-down method counts a lower layer as plain only when it is Normal at 100 % in every channel.
- Locks (`PaintDocument.Locks.cs`, `LayerLocks`, native version 12): `SetLayerLocks` / `ChangeLayerLocks` (one undo step for several layers); `EffectiveLocks` adds the locks of every group a layer is in, with All implying the others. Refusals throw `LayerLockedException` (`LayerOpRefusal.Locked`, naming the layer or group that holds the lock) before anything changes. Transparency: strokes (2D dabs and `ApplyPixel` mesh dabs), `Fill`, `Gradient`, `ReplacePixels` and `BakeFilters` keep every pixel's alpha and move only its colour (source-atop in straight colour, the selection's amount in the same single rounding; a pixel with alpha 0 keeps its stored RGB); erasing, cutting, paths and moving a selected part are refused; moving or transforming the whole layer is allowed. Pixels: every pixel edit, the fill value, merges into or from the layer are refused; a whole-pixel move of the whole layer and the mask stay allowed. Position: `Transform` / `TransformLayers`. All: also attributes, mask and filter edits. Name, visibility, order, grouping, duplicating (the copy keeps the locks) and deleting are never refused. Resampling keeps the locks.

## Reference compositing and graph boundary

Layer blend modes cover Photoshop's set except Dissolve (26 modes: separable ones with Photoshop's formulas, including its soft light, and the non-separable Hue/Saturation/Color/Luminosity with the W3C formulas), combined by W3C source-over with correct partial-alpha terms; clipping and adjustment layers use the same blend colour. The GPU tile compositor implements the same formulas. Equality with Photoshop's own rendering has not been measured. Composition is performed in stored RGB space and rounded to RGBA8 after each layer. Each layer composites with its blend mode and opacity in the channel (`StackEntry.BlendMode` / `Opacity`, resolved from per-channel settings by `Plan`). This is a reference raster path, not proof of PSD application matching. Normal-channel pixels can be retained and inspected, but this core does not implement tangent-vector normal blending.

`CompositeRegion` computes the same bytes as the per-pixel reference (`CompositePixel`) a row span at a time: unfiltered raster and mask tiles are read in place (uniform tiles and fill layers through one shared expanded tile per call; only filter output is copied), and the span code takes only shortcuts that give the formula's own bytes — a transparent source pixel, an opaque source at amount 1 in Normal mode, a transparent backdrop (the colour is the source's, the alpha a; not used below a = 1e-300 where a·c could be subnormal), an opaque backdrop (a is exactly 1, so the division drops out) — and looks the separable modes' blend colour up in a 256×256 table of the very values `BlendRgb` gives (one 512 KiB table per mode, made once on the calling thread). `CompositeRegions` composites several regions in one parallel pass, each from a caller-supplied backdrop (the composite of the plan's top-level entries below `Start`, in the job's pixels or read from another array) and optionally keeps the composite below `CaptureAt`; the display's CPU path keeps such copies to redraw only from a changed layer up. Inside groups a job may likewise start a group's contents from a copy (`Resume`) and take copies on the way (`Captures`): a `NestedCopy` addresses a group of an entry by plan indices and holds the group's inner result after its first `Index` children — from transparent for an isolated group (and one with clipped layers), onto the composite below it for a pass-through group (so it holds that backdrop). A group with nothing in a tile is still skipped there, and the copies inside it are filled with the group's start. Groups clipped to a base are not addressed. A pass-through group at opacity 1 without an effective mask composites its children straight onto the backdrop (its fade would return them unchanged). `CompositeSampledRegions` does the same on the grid that keeps one pixel of every step × step square (step divides the tile size, width and height): each loaded tile, filter output included, is replaced by its sample before the same per-pixel evaluation, so every sample is exactly the full composite at its pixel (the display's reduced preview during drags; about 1/step² of the work, less parallel). Tests compare against a frozen copy of the formulas (`Tests/Editor/Support/FrozenCompositor.cs`). The per-tile work is done a rectangle at a time (a whole tile, or a band of rows when there are few tiles), one layer after another, and the blends and clipping go through `CompositeKernels.Current` when an assembly has registered kernels there (they must return the managed loop's bytes, or decline a case and let the managed loop run). The core itself stays engine-independent and works without any kernel; `Runtime/Burst` (`Yozolab.YoluPainter.Core.Burst`, compiled only where com.unity.burst is installed) registers Burst-compiled kernels for the colour blend, clipping and the Normal channel's blend and clipping (FloatMode.Strict, tables made by managed code, nothing allocated, arrays pinned for the call).

ID colours (`IdColorSelection.cs`): `IdMapColors` reads an ID map's texel as 8-bit RGB (the map stores 8-bit × 257; `(v × 255 + 32767) / 65535`, the overlay's rounding), compares by the largest channel difference (the magic wand's tolerance, 0–255) and never gives a colour for Empty texels. `SelectionMask.FromIdColors(document, idMap, colours, tolerance)` selects (0 or 255) every texel within the tolerance of one of the colours (padding included, Empty never), tile by tile in parallel; the map must be the ID kind and the document's size. The generator `IdColor` (type 6) gives 1 where the texel matches one of its colours (at most 32, in the order added, no repeats) and 0 elsewhere, then levels, invert, breakup and blend as for every generator; without colours it passes its input through and says so. The ID map's colours come from `MeshMaps.IdPalette` (see `MeshMaps/MeshRegions.cs`): for n parts, the RGB lattice with the fewest levels q per channel that holds n non-grey colours (q³ − q ≥ n), so any two colours differ by at least 255/(q − 1) in one channel (17 up to 4080 parts), visited in a golden-ratio stride so consecutive parts get far-apart colours. Parts are split by `MeshMaps.MeshRegions` (UV islands and mesh parts), the same rule the editor's polygon fill uses.

`DependencyGraph` stores typed declarations for later effect/anchor evaluation. Connections enforce same texture set, input type, optional semantic channel, one source per input, acyclicity, and lower-layer/earlier-effect order. Invalid node/layer-order changes are atomic. Referenced deletion is rejected. Invalidation increments source and downstream revisions, including hidden consumers. Actual filter/generator execution, halo-aware dependency scheduling (display-side tile change tracking exists: `ChangeSerial` / `TryGetChangedTiles`), graphs in native persistence, multi-channel atomic strokes, masks and pressure-curve editing are later work.
