# PSD compatibility and safety gate

Status: implemented **limited RGB8 raster codec with layer features (blend modes, clipping, raster masks, groups) and non-rendering metadata acceptance**, 2026-10-02. This is not broad Photoshop/CLIP STUDIO compatibility, a production PSD backend, or completion of the full painting specification.

## What actually works

`Yozolab.YoluPainter.Core.Psd` is pure C# with no Unity or third-party runtime dependency (it uses the core's `LayerBlendMode` and `CpuCompositor` arithmetic). It writes an actual PSD version 1 containing raster layers, straight RGBA8 channel data, bounds, opacity, visibility, the 26 blend modes that have a native equivalent, clipping, raster user masks (rectangle, default colour, disabled flag, density), Unicode `luni` names, positive unique `lyid` IDs, and a current merged composite. Physical PSD layer records are bottom-to-top; the public DTO is top-to-bottom. Layer color samples under zero alpha and outside the canvas are retained exactly.

The reader accepts raw and PackBits/RLE layer and merged data. The writer deliberately emits uncompressed raw channels. It is a bounded whole-document prototype, not the future streaming/tile-backed codec required for large production documents.

### Public API and integration

- `PsdCodec.Read(byte[], PsdLimits = null)` and `Read(Stream, PsdLimits = null)` return `PsdReadResult`
- Result mode is `EditableRaster`, `PreserveOnly`, or `Rejected`; `Document` is **null unless editable**
- Result `Diagnostics` identify unsupported feature keys/resource IDs and source byte offsets/lengths, subject to a diagnostic-count cap
- `CopyOriginalBytes()` returns a fresh, complete unchanged source copy when source retention succeeded
- `PsdCodec.Write(PsdDocument, PsdLimits = null)` creates a new native raster PSD snapshot
- `PsdCodec.WriteEdited(PsdReadResult origin, PsdDocument edited, PsdLimits = null)` rejects PreserveOnly and Rejected origins before writing
- `PsdDocument` has Width, Height, Layers and an optional `CompositeRgba` (top-down straight RGBA8 merged image for the writer; null = the writer composites the layers itself with the reference arithmetic; the reader leaves it null). `PsdRasterLayer` has Id, Name, Left, Top, Width, Height, Opacity, Visible, BlendMode, Clipping, Mask, and top-down straight `PixelsRgba`. `PsdLayerMask` has Left, Top, Width, Height (canvas coordinates), DefaultColor (0/255, outside the rectangle), Enabled, Density and top-down `Pixels` in Photoshop's sense (255 shows)
- `PsdCodec.BlendKey(LayerBlendMode)` / `TryGetBlendMode(key, out mode)` expose the key table; pass-through (groups only) has no raster-layer key
- A group is a `PsdRasterLayer` whose `Children` (top to bottom) is not null (`IsGroup`); it has no pixels or rectangle, its `BlendMode` is `PassThrough` or an isolated mode, and `DividerId` is the layer ID of its bounding divider record (0 = none). `PsdLimits.MaxGroupDepth` (default 32) bounds nesting on read and write
- Two diagnostic codes never block editing and can appear on an EditableRaster result (`PsdCodec.IsInformational`): `PsdCodec.NotCarriedIntoExport` ("NotCarriedIntoExport", one per kind of accepted non-rendering information, with a count) and `PsdCodec.CompositeDiffers` ("CompositeDiffers", see the merged-image rule). Every other code belongs to a PreserveOnly or Rejected result. The application should list the informational ones after an import
- `PsdBridge.Export(document, channel)` maps native raster layers and groups (nested, any depth within the budget) with their blend mode, clipping flag, mask (enabled/disabled, density), visibility, opacity and layer locks (`lspf`, `PsdRasterLayer.Locks`), and stores `document.Composite(channel)` as the merged image. The blend mode and opacity written are the layer's in the exported channel (`PaintLayer.BlendModeIn` / `OpacityIn`: a per-channel setting when the layer has one for that channel, native version 14), so the layers recomposite to the merged image of that channel; a PSD holds one channel, so the other channels' settings are not in it. It refuses fill and adjustment layers, any other kind and inverted masks instead of flattening them. Opacity and mask density are rounded to the nearest 1/255. `PsdBridge.Import` maps them back into native groups (`PaintDocument.ValidateStructure` is run), carrying PSD layer and divider IDs inside the native layer IDs so that a re-export writes the same IDs. Import is blocked if layer pixels, or mask samples that differ from the mask's default colour, lie outside the canvas

The codec performs no filesystem writes. The application must use `WriteEdited` for imported-source edits, and must not build a partial native DTO from an unsupported import to bypass that guard. Copying original bytes is a backup/preservation operation, not permission to replace an externally modified file. The application owns immutable save snapshots, external-change detection, and transactional path replacement. Do not mutate DTOs during writing.

### Accepted non-rendering information (user decision, 2026-10-02)

Typical Photoshop-saved PSDs carry information that does not change how the image renders or is interpreted. It is accepted instead of forcing PreserveOnly, but never silently: each kind found is reported once (with a count) as `NotCarriedIntoExport` — "kept in the original PSD bytes, not carried into exported PSDs". The original bytes stay retained (the application stores them inside the `.ylp`), so nothing is lost; a PSD exported from the native document simply does not contain it. Anything that can change rendering or interpretation stays PreserveOnly with its diagnostic.

### Exact editable acceptance rules

PSD v1; RGB8; 3 merged RGB channels or 4 with explicit negative-count merged-transparency flag; non-empty raster layers, balanced folders (empty folder and divider records) and pixel-less adjustment records (one `nvrt`/`levl`/`hue2` block mapped as above); one of the 26 mapped blend keys (or `pass` on a folder); clipping 0 or 1; at most a raster user mask (channel −2 with its mask data; no feather, no vector or "real" mask fields, mask flags only "disabled" and "parameters applied" with the user-density parameter); neutral or absent Blend-If ranges; layer flags limited to transparency lock, hidden and bit 3 (plus bit 4 on folders and dividers); only the image resources and document blocks in the accepted list; no global masks, unknown tags or unsupported compression. Raster layer channels must uniquely contain R/G/B and optionally transparency and −2. Additional layer data interpreted: `luni`, `lyid`, `lsct`/`lsdk`, `iOpa`/`clbl`/`infx`/`knko`/`tsly`/`brst` at their default values only, and the non-rendering blocks of the accepted list. Empty raster layers are currently PreserveOnly. Duplicate/missing IDs are never assigned replacement identities automatically (a divider record may have no ID).

The reader regenerates the merged image with the same per-pixel arithmetic the native document will use (`CpuCompositor.EvaluatePixel`: `Blend`/`ClipOnto`/`Fade`, isolated and pass-through groups, one rounding per layer step, mask factor 1 − density × hide), white-matted. For a plain stack (every layer normal, no clipping, no mask, no group) the stored image must agree within one byte per applicable channel, otherwise the file is PreserveOnly: a plain stack has one well-defined result, so a difference means a stale image or a misread. When blend modes, clipping, masks, groups or adjustment layers are used, the difference is reported as the non-blocking `CompositeDiffers` diagnostic (with the largest difference) instead: Photoshop's own arithmetic for those features is not measured, and refusing every file it wrote would make the features useless. Files written by this codec agree exactly in both cases. Neither check is a proof of Photoshop equivalence.

Recognized names/IDs, pixel semantics, blend modes, clipping flags and masks (rectangle, default colour, samples, disabled flag, density) survive editable rewrites; a file written by this codec is rewritten byte-identically. Full-file byte equality is **not** promised for other editable rewrites: RLE becomes raw, the legacy Pascal fallback can be normalized, default-valued settings and neutral Blend-If ranges are omitted, mask data is normalized to 20 bytes, and the merged cache is regenerated. The original remains available separately.

## Alpha and color contract

Layer data is straight RGBA8. All transparent-pixel RGB remains untouched. Compositing uses the native `CpuCompositor` arithmetic in encoded sample space, rounding once per layer step (so the writer's merged image and the native composite of the imported document are byte-identical). This is explicitly **not** a linear-light/sRGB-conversion implementation.

Merged PSD RGB is white-matted and merged transparency is its fourth channel, signaled by negative layer count. ImageMagick and psd-tools correctly remove that matte. Pillow exposes the stored white-matted RGB directly; its output alone is not a transparent-render fidelity oracle. Undo/save must retain the straight layer data, not recover source pixels from the quantized merged preview. Low-alpha colors in an un-matted merged preview can differ because 8-bit matting loses precision.

The output has no ICC profile. Native documents must declare their sample interpretation in the application; this codec must not label an arbitrary imported profile as sRGB.

## Resource and parser safety

Default limits (caller-configurable within PSD v1 dimensional constraints):

| Budget | Default |
|---|---:|
| Input / retained source bytes | 128 MiB |
| Encoded output bytes | 128 MiB |
| Maximum single dimension | 8192 |
| Canvas and per-layer pixels | 16,777,216 |
| Layer count | 256 |
| Decoded raster + working pixel buffers | 256 MiB |
| Interpreted/opaque metadata bytes inspected | 4 MiB |
| Layer-name UTF-16 code units | 4096 |
| Diagnostic entries | 128 |

Mask rectangles are bounded by the same dimension and pixel limits as layer rectangles, and mask samples count toward the decoded-pixel budget. Length-delimited readers validate parent bounds before reads, allocations or skips. Unsigned PSD lengths are checked before conversion to managed indices. Rectangle differences use 64-bit arithmetic; RLE rows cannot expand past their declared width and must fill exactly that width. RLE row tables and compressed row lengths are independently bounded. Compression that is not implemented is never passed to an unchecked decompressor. Byte-array inputs are cloned; returned original-byte copies do not alias retained data.

These are logical allocation budgets, not a hard process RSS ceiling. Caller-owned source buffers, retained source, stream staging, CLR object overhead and garbage collection add memory. `Read(Stream)` consumes at most the source cap plus one lookahead byte and leaves the stream open. `Read(byte[])` cannot prevent the caller from allocating an oversized input first. Current writer and reader are unsuitable as the final low-memory 4K/many-layer backend without streaming/tile integration. No cancellation/background UI scheduling is implemented inside this codec.
