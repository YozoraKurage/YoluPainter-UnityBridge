# Architecture and invariants

## Source layout

Folders group files by concern; namespaces follow folders only where they already did (`Core.Brushes`, `Core.MeshMaps`, `Core.Paths`, `Core.Persistence`, `Core.Psd`, `Core.Shelf`, `Editor.Preview`, `Editor.LilToon`, `Editor.LilToonApply`, `Editor.MaterialApply`). Everything else in `Editor` is `Yozolab.YoluPainter.Editor`.

- `Runtime/Core` — the engine-independent document, brush, compositing, selection and filter code (see `Runtime/Core/README.md`). `Runtime/Core/Shelf` holds the project's resources (images shared by every texture set: content, origin, `ProjectResources`, the strict `RgbaPng` codec, built-in images, whole-image resampling).
- `Runtime/Burst` — `Yozolab.YoluPainter.Core.Burst`, the Burst-compiled inner loops of the CPU compositor, registered as `CompositeKernels.Current` at load. Compiled only where com.unity.burst is installed (`versionDefines` + `defineConstraints`); without it the core's managed loops run.
- `Editor/Window` — `TexturePaintWindow`, one partial class split by concern: the class file holds state, lifecycle and `OnGUI`; `Keys` the shortcuts; `Shell/` the frame (layout, menu bar, options bar, tool strip, status bar, dock columns, tab groups and `DockLayout`, panels detached into `PainterPanelWindow`, the Properties panel host); `Panels/` the dock panels (color, texture set, layers, assets, thumbnails); `Canvas/` the 2D canvas view, input routing and brush cursor; `Tools/` brush settings and strokes, canvas tools, selection, transform, paths and the tool sections of Properties; `Layers/` the layer, mask, filter and normal sections; `Model/` the 3D view (surface tools, lighting, the pseudo scene and its environment, shadows and tone mapping, the material chosen per texture set and its channel routes, what the view shows (material, one channel, one mesh map), pose, mesh maps and the `MeshBakeWindow` baker, lilToon); `Project/` new project, project configuration, texture sets (the window keeps the current set's document, layer and slot in its fields and swaps them on switching), the project's resources (import, place as layer, source checks) and file I/O (.ylp, recovery, PSD, image export).
- `Editor/Api` — the plugin API (its own assembly, `Yozolab.YoluPainter.Api`: `PainterPlugin`, `IPainterPluginBuilder`, `IPainterSession`; see `PLUGIN_API.md`). `Editor/Plugins` — the registry that loads plugins; the window side (menus, the session over the open document) is `Window/TexturePaintWindow.Plugins.cs`.
- `Editor/UI` — the paint UI kit (`PaintTheme`, `PaintGui`, `PaintIcons`, `PainterToolIcons`, `OffscreenGui`, dialogs) and `UI/Icons`.
- `Editor/Localization` — `L` and the gettext catalogs.
- `Editor/Preview` — the isolated model preview and surface geometry, the material view (`PreviewMaterialBinding` maps channels to verified properties, `PreviewMaterialView` owns the material copies and packed textures, `PreviewMaterialEdits` holds the Material panel's preview-only values) and the pseudo scene (`PreviewSceneSettings`). `Editor/LilToon`, `Editor/LilToonApply` — lilToon inspection and the explicit apply command. `Editor/MaterialApply` — the explicit "Apply to Material…" command, the only code that writes Material panel values into a source material.
- `Editor/Gpu` — the tile compositor, GPU mesh baking, normal output and the GPU brush probe. `Editor/Brushes` — brush tips, the brush library and importers. `Editor/Ylp` — the .ylp importer and archive content. `Editor/Settings` — project settings. `Editor/Shelf` — reading Unity textures and image files for resources (`UnityTextureReader`, `ImageFiles`) and the user's library folder.
- `Editor/PackagePaths` finds the package root (package info, else the Editor assembly definition), so icons, catalogs and shaders load wherever the package is installed.
- `Tests/Editor` mirrors these areas (`Core`, `Brushes`, `Paths`, `Psd`, `Persistence`, `MeshMaps`, `Preview`, `Gpu`, `UI`, `Window`, `Support`).

## Source and adapters

`Runtime/Core` is engine-independent C#8 using System only. Unity compiles it as an editor-only assembly with no engine references (`noEngineReferences`); its tests run as ordinary Unity EditMode tests. Its source archive is RGBA8 straight alpha, bottom-left row order. Color and emission currently retain untagged encoded samples; no ICC transform, HDR or Photoshop rendering equivalence is claimed. Scalar channel UI replicates a scalar into RGB. A layer composites with its own blend mode and opacity, or, in a channel where it has a per-channel setting (`ChannelBlend`, native version 14; Substance Painter's per-channel blending), with that channel's mode and/or opacity instead; visibility, mask and clipping stay shared. `CpuCompositor.Plan` resolves the values per channel into each `StackEntry` (`Opacity`, `BlendMode`), and every consumer — the span compositor, the per-pixel reference, merges, the GPU tile compositor and its block signatures, PSD export — reads them from there or from `PaintLayer.BlendModeIn` / `OpacityIn`. The Normal channel composites as tangent-space unit vectors (`NormalMaps`: renormalized source-over, Overlay = Reoriented Normal Mapping detail, other modes replace; adjustments stay encoded-space), and its output is the painted composite flattened onto flat with the Height-derived normal as the RNM base (opaque, OpenGL Y+; DirectX only for files).

The authoritative CPU brush is the correctness/reference backend for this checkpoint. It allocates only touched sparse tiles; uniform and zero tiles have compact representations. Before/after tile references use copy-on-write so one stroke can be canceled or undone without brush replay. Tile exports are detached arrays; UI never changes source tile arrays behind the history service. Source and history budgets are payload bytes, not total managed heap or OS memory measurements.

The window chrome is custom-drawn IMGUI (`Editor/UI`: `PaintTheme` colors and text styles, `PaintGui` widgets drawn from rectangles and rounded rects instead of Unity's built-in control styles, `PaintIcons` for the bundled Fluent UI / Phosphor icons, `PainterToolIcons` for replaceable tool icons). `TexturePaintWindow.Shell.cs` lays out the menu bar, options bar, tool strip, view area and status bar; `TexturePaintWindow.Dock.cs` draws the texture set, layers and properties panels. All UI text goes through `L.Tr` (`Editor/Localization`, gettext `.po` files, English source strings as keys, `msgctxt` for the same English with two meanings). `OffscreenGui` renders the window into a RenderTexture in batch-gl so its look can be checked where the GUI-mode editor cannot draw.

`TexturePaintWindow` (`Editor/Window`) uses one IMGUI event route with `Event.pressure`, explicit mouse capture, pressure curve, and fallback semantics provided by Unity. A stroke freezes its brush. A stroke paints the selected channel with the foreground colour, or, with the brush's material on (Properties ▸ Brush ▸ Brush Material), every checked channel with its own value through `PaintDocument.BeginMaterialStroke`: the dabs, dual brush and per-pixel coverage are computed once and applied to each channel's surface with the one-channel arithmetic (each channel ends with the bytes a stroke of it alone gives), the rollback of all of them counts against one budget, channels the layer has switched off are switched on inside the stroke's single undo step, and a cancel restores every channel and switches them off again. Escape, focus loss, reload and play transition roll back the active stroke. Structural controls and camera navigation are disabled during painting. Rendering can skip frames; committed dab samples are not discarded. The 2D reference sampler is arc-distance based. The surface adapter resamples screen motion, rerays visible triangles and rasterizes surface coverage in UV, never draws a line between distant UV islands. With symmetry on, each 3D dab is joined with its mirror image across a plane in the model root's local axes (`SurfaceSymmetry`, see `Editor/Preview/README.md`; the settings are window state, not brush settings); 2D canvas strokes are not mirrored.

マテリアルの範囲編集（`PaintDocument.MaterialRegions.cs`）: `FillMaterial` は各 `ChannelPaint` の値を同じ範囲に塗り、
`GradientMaterial` は各値から透明へ薄くする（形・端点・不透明度だけを `GradientSettings` から使い、From/To は各値/透明に置き換える）。
単チャンネルの `Fill` / `Gradient` と同じ `EditRegionTiles` と画素の式を通るので、各チャンネルの結果は単独で塗った場合とバイト一致する。

## 2D canvas view

The 2D canvas view (zoom, pan, rotation, horizontal flip) is display-only. `CanvasView` (`Editor/Window/Canvas`) maps canvas pixel coordinates (bottom-left origin) to GUI coordinates: fit-to-view times zoom, centred on the view centre plus pan, mirrored and then rotated about the image centre. Without rotation or flip it is the earlier float formula, so the display and the pixel coordinates of input are unchanged. Every input (brush samples, tool drags, move-tool handle hits, eyedropper, path points) goes through its inverse, so source, stabilizer, taper and curve work in pixel coordinates whatever the view; the brush tip angle stays in pixel space (Photoshop's behaviour, not CLIP STUDIO's screen-relative angle) and pen tilt is turned from screen to canvas axes. The image and the selection and mesh-map overlays are rotated by multiplying `GL.modelview`, not `GUI.matrix`: IMGUI clips in pre-`GUI.matrix` coordinates, so a rotated `GUI.matrix` let the image spill out of the view (checked offscreen in batch-gl). Lines, handles and markers are drawn at mapped points. Rotation and flip pivot on the view centre, are refused during a stroke or drag, and are window state serialized across domain reloads, not stored in the `.ylp`. The 3D view is unaffected.

## GPU status

`TileGpuCompositor` holds a composite texture, a single layer upload tile, and two ping-pong work tiles. It recomposites only the tiles `PaintDocument.TryGetChangedTiles` reports as changed since its last update, with one layer at a time resident; it does not allocate a full GPU texture for every layer. Layers without a tile are skipped (exact, since blending a transparent source is the identity). Structural changes (layer order, visibility, opacity, blend — per-channel settings mark only their channel —, enabled channels), a channel switch or a different document recomposite every occupied/previously occupied tile; at 4K that is still seconds and needs a layered cache. Work tiles use point sampling: the second pass reads the first pass's result, and bilinear filtering blended neighbors on llvmpipe. Where `Graphics.CopyTexture` is unavailable (Unity disables it below OpenGL 4.3 even if the driver has ARB_copy_image), finished tiles are drawn into the composite with a plain copy pass (TileComposite pass 1) instead. Display compositing is a personal setting (Automatic / GPU / CPU, `CompositorBackend`); Automatic means GPU where it is usable, except on a software renderer (llvmpipe, softpipe, lavapipe, SwiftShader, WARP by device or vendor name), where it means CPU, and saving, exporting and recovery always composite on the CPU whatever is chosen. The CPU path (CPU chosen, or no usable GPU: no device, no ARGB32 render texture, or a shader with compile errors per `ShaderUtil.ShaderHasError`) composites with Core's `CpuCompositor.CompositeRegions` (several regions in one parallel pass, each from a backdrop): like the GPU path it keeps per block the signatures of the top-level entries and, within the same `ResidentBudgetBytes`, a managed copy of the composite below the first entry that differed (taken by compositing the whole block at the first difference); a block that changes again just above its copy composites only its changed tiles (`CoverTiles` rectangles) from the copy up, anything else from transparent, and the copies are dropped when something below them changes. Where a render texture and a way to copy into it exist (CopyTexture Texture2D→RT, else the TileComposite copy pass) only the changed tiles (a whole block when all its tiles changed) are staged in small Texture2Ds and copied into the display render texture; otherwise a CPU-side Texture2D is reloaded whole. The display is byte-identical to the CPU reference on every path. Display compositing is scheduled in slices (`Update(doc, channel, CompositeSchedule)`, called by the window on every repaint): the change journal's tiles become per-block pending work, and whole blocks are composited — urgent ones (the stroke in progress) always in that repaint, then those the 2D view shows (nearest its centre first), those the 3D view's UVs use (UV bounding boxes of the current slot's triangles), and the rest, the longest-waiting first within each class — until the personal per-repaint budget (Compositing time per frame, default 10 ms, 0 = no limit) is spent; the window asks for another repaint while work is left. A displayed block is therefore its previous picture or the new one, never a half-composited block, and pending work always composites the document as it is then (a slider that keeps moving leaves no stale work). A different document or channel drops the pending work, clears the display and starts over; Dispose drops it too. The GPU path checks the time between blocks (the GPU's own execution is not timed); the CPU path puts as many blocks into one `CompositeRegions` call as its measured costs (per layer-pixel composited, per pixel sent) predict to fit. The whole-frame Texture2D path (`CpuFrame`) and the lighting and Height compositors are not sliced. During a drag on the CPU path, when the pending work would take at least four budgets, the waiting tiles first show an exact 1/4-sampled composite (`CpuCompositor.CompositeSampledRegions`; each sample is the full composite at its pixel) drawn scaled into the display, until full resolution replaces it block by block (the canvas shows a "Reduced preview 1/4" badge meanwhile). Saving, exporting, recovery, the eyedropper and every other reader of composites use the CPU reference, never the display. Core's span code reads unfiltered tiles in place and takes only shortcuts that reproduce the formula's bytes (transparent or opaque backdrop, separable blend colours from 256×256 tables of the same doubles), works a tile rectangle at a time and hands each blend and clip to `CompositeKernels` (Burst where installed, FloatMode.Strict, byte-identical to the managed loops); see `Runtime/Core/README.md`. A GPU that was wanted but is unusable sets `FellBackToCpu` (the status bar says so). The Normal output pass runs on the GPU only where GPU compositing is usable. Layer and mask filters (`FilterEngine`) and fill layers' projected images are evaluated on the CPU, block by block with their halo, into a budgeted per-tile cache keyed by the stack revision and the newest source tile revision inside the halo; compositors read `CopyOutputTile`, and a source change in a filtered layer is widened by the halo (or to every tile for a global stack) when `TryGetChangedTiles` is asked. Graph-driven dependency scheduling is not handled. Source byte precision remains independent of GPU result precision.

The change journal (`ChangeSerial` / `TryGetChangedTiles`) is display-cache state only: it is not part of undo history or persistence. Pixel writes report through `SparseTileSurface.SetPixelInternal` and `Restore`, which every stroke, cancel, undo and redo goes through; history-external mutations and composite-affecting structure changes force a full answer. It can report tiles that changed and changed back.

`OrderedBrush.shader` and `GpuBrushProbe` are an explicit G0 GPU-stamp experiment. They are not part of the authoritative brush path. The probe reports error against the CPU reference after test-only synchronous readback. Runtime GPU failures do not replace CPU source. Shader correctness, device orientation, project color-space display, copy support and graphics-driver behavior remain Unity gates.

## Preview ownership

`IsolatedModelPreview` reads supported source renderers, copies Mesh objects, transforms snapshot geometry, and builds only tool-owned MeshFilter/MeshRenderer objects in PreviewRenderUtility. It never instantiates a user's GameObject/Prefab or scripts. It owns its mesh/material lifecycle. All intersections use that snapshot, not global Physics. The neutral opaque preview intentionally does not reproduce arbitrary displacement, alpha-test/transparency, or target lilToon material appearance.

The material view (`Shading = Material`) draws each slot with a private copy of a material (same shader, keywords and values; Material panel values on top). Per texture set the window chooses which (`PreviewMaterialChoice`, window state keyed by the set ID, not in the `.ylp`): the slot's own material (the default and the former behaviour), a material asset of the project (remembered by GUID and local file ID), or a shader (a default material made in memory for the preview, kept across script reloads and destroyed when the window closes); a choice whose asset or shader is gone falls back to the own material with a notice. The painted composites go only into properties with a known reading: lilToon through `LilToonAdapter` (version, variant, properties, compiled features; never guessed for an unverified lilToon), the built-in Standard shader against Unity 2022.3's `UnityStandardInput.cginc`, and for every other shader a mapping guessed from property names and `[Normal]`/`[MainTexture]` flags (the names of the export templates: `_MainTex`/`_BaseMap`, `_BumpMap`/`_NormalMap`, `_EmissionMap`, `_MetallicGlossMap` R + A, `_ParallaxMap`/`_HeightMap`, …; labelled as guessed). The Material panel's Channels list overrides the route of each channel (`PreviewChannelRoute`: a 2D texture property and a packing allowed for that channel, or "not shown"); routes that do not fit the shader, or that would put two packings into one property, are not used and say why. Data channels are flattened (value × alpha) and packed by `PreviewChannelPack.shader` into the copy's own RenderTextures; the source, the chosen material and their textures are never written ("Apply to Material…" refuses a material made from a shader). Slots whose shader is missing, fails to compile, or needs an SRP fall back to the neutral view with a reason. The 3D view can also show one channel (or the selected layer's mask) or one baked mesh map of every texture set unlit, as its values (`SetUnlitTextures`; keys C / Shift+B / Shift+C and the header button), with no lighting, environment, shadow or tone mapping. Picking and painting do not depend on the view. The pseudo scene (light direction, intensity, colour, ambient, background, camera presets, environment, shadows, tone mapping) only changes the preview's own lights, its scene's overridden lighting (`Unsupported.SetOverrideLightingSettings`, restored by `EndPreview`) and the preview materials; the default reproduces the former neutral lighting. The environment (built-in procedural sky or a Cubemap / latitude-longitude texture asset, read on the GPU only) is baked into a 256² cube, convolved per Unity reflection mip with GGX, and projected to SH from a 64 × 32 readback (only when the source changes; a rotation turns the SH analytically); the neutral materials switch to `PreviewSurfaceLit` (the neutral shader plus the SH diffuse, a fixed-roughness dielectric reflection and the shadow lookup) only while an environment or shadows are used, so the former `PreviewSurface` is unchanged; the material view gets them as the ambient probe and custom reflection. Self-shadowing uses the preview's own 2048² light-depth map fitted to the model's bounding sphere (not Unity's shadows, which depend on the project's quality settings and cannot be softened in the built-in pipeline): the lit neutral shader reads it with a rotated 16-tap PCF; the material view multiplies a shadow overlay that darkens lit faces to the ambient/(ambient + direct·N·L) ratio. Tone mapping (Neutral, ACES) and exposure render the camera to a half-float target and map it into the former 8-bit target; they never touch texture values, exports or the 2D canvas.

The polygon fill (tool key 4, `Window/Tools/TexturePaintWindow.PolygonFill.cs`) picks a triangle on the model (the preview's BVH) or under a UV point of the current set's slot on the 2D canvas (`SurfaceRegionIndex`), follows it to a region (triangle, mesh part, UV island, material; the same setting as the 3D pick) and adds the region's UVs to a Core `TriangleFill`, which the window holds as its active stroke: a drag adds every region it passes over, release commits one undo step, and Escape, focus loss, reload, play mode and exceptions cancel it like a brush stroke. The pixels equal the bucket's 3D click (Fill of the union's `FromTriangles` selection), inside the selection, under the layer's locks; on a mask paint writes white (shows) and erase black (hides) as the thumbnail shows them. The region under the pointer is tinted in the 3D view and outlined on the 2D canvas; it is looked up only when the pointer's triangle changes and redrawn only when the region changes.

The ID colour select (tool Shift+W, `Window/Tools/TexturePaintWindow.IdSelect.cs`) and the ID colour generator's eyedropper read the current texture set's baked ID map only while it is current (`MeshMapSet.TryGetUsable`: same model, size, slot and bake settings; otherwise nothing is selected or added and the reason is shown). The colour is the clicked pixel's texel on the 2D canvas, or the texel at the hit face's UV in the 3D view (faces of the current set only). The tool selects every texel within the tolerance (`SelectionMask.FromIdColors`, one undo step, Shift/Ctrl/Shift+Ctrl like the other selection tools); the eyedropper adds the colour to the generator (Ctrl+click takes it out, one undo step each) and pins the generator's ID map to that bake, because the colours only mean something for it: a rebake under other conditions then passes the generator through with the reason instead of silently selecting other parts. The ID map's parts are split by Core's `MeshRegions`, the rule `SurfaceRegionIndex` uses for the polygon fill (mesh parts and UV islands), and coloured from `IdPalette` (well-separated lattice colours, never grey); vertex colours are taken per triangle (majority of its corners), never interpolated, so every texel is a colour of some part.

`SurfaceGeometry` creates adjacency using quantized geometric edge positions, so distinct UV vertices can connect across seams. Material slots, connected components, facing tests and camera visibility limit a surface dab. Non-manifold edges stop traversal. Duplicate-position geometry, overlapping UVs, highly folded meshes and tiny scale require further fixtures. UVs outside [0,1] are not treated as UDIM/repeat. Budgets reject the whole dab, so the window cancels that stroke instead of committing incomplete coverage.

## Persistence

The .ylp file format, its versions and the migration rules are specified in `YLP_FORMAT.md`: an integrity layer (zip, mimetype, SHA-256 manifest, `YlpArchive`), a content format recorded in `ylp.json` (`YlpFormat`: format number, the application and Unity versions that saved and created the file; files without it are format 1), and per-entry codec versions. Opening upgrades older formats in memory step by step and refuses newer ones without touching any entry; saving always writes the current format. Since format 4 (manifest `YOLUPAINTER-YLP-3`) the project's resources are `resources.json` and one `resources/<content hash>.png` per distinct content, both source entries: a listed content that is missing, does not decode, has another size or other pixels refuses the whole file.

`DocumentBinary` serializes version, project/layer IDs, attributes (version 12 locks, version 14 per-channel blend settings), enabled channels and exact sparse tile RGBA. It rejects unknown versions, duplicate IDs/tiles/channels, impossible dimensions, truncation and excess sizes. Raster data with alpha zero retains RGB. Persisted procedural state lives in the layer's ordered effect stacks (content and mask; version 9 filters, version 11 generators), in the 2D/3D path records (versions 8 and 10) and in fill layers' image IDs and projection (version 16); see YLP_FORMAT.md. The dependency validator is not yet wired to them, so the stacks are evaluated in their stored order without a graph scheduler.

`YlpArchive` / `YlpStore` hold the user's document as one `.ylp` file: a zip written by a minimal in-house writer (the first entry `mimetype` stored uncompressed for magic detection, PNGs stored, other entries deflated when smaller) with `manifest.sha256` listing the SHA-256 and length of every entry. Reading uses System.IO.Compression and refuses wrong order/mimetype, unsafe names, unlisted or missing entries, length/hash mismatches, entries inflating past their declared size, budgets and newer manifest versions. Since format 3 (manifest `YOLUPAINTER-YLP-2`) a project holds several texture sets: `project.json` lists them (id, name, material slot, the current set) and each set keeps its own `sets/<id>/document.utpaint` (the only authoritative source of that set), selection, mesh maps and composites; `composite/<channel>.png` and `thumbnail.png` are derived outputs for the Unity importer and outside viewers. A save builds and re-reads the archive in memory, takes a cooperating lock (`<file>.lock~`), checks the expected file token (full SHA-256), writes `<file>.saving-<guid>~` with Flush(true), re-reads it, checks the token again and then replaces the file once (`File.Replace`), moving the previous version into `<file>-backups~/` unless the user's settings say otherwise. Names ending in `~` are not imported by Unity. The periodic external-change check compares length and modification time first and hashes only when they differ.

Recovery checkpoints still use `GenerationStore`: `GenerationStore` creates a new same-root staging folder, writes and Flush(true)s each file, generates a sorted checksum manifest, rereads/verifies it, moves the directory under generations, checks current expected token+hashes again, then replaces the pointer last. Old generations stay intact. A cooperating-tool lock serializes this tool's saves. Noncooperating external apps are detected but not locked; a hash check is not a transaction lock against all outside writers. Directory fsync and power-loss guarantees differ by platform and are unverified. Failure after pointer replacement can mean a new committed generation despite an interrupted acknowledgement; callers must reload current before retry.

The current UI pauses input during explicit save. It creates an immutable native byte snapshot before writing. This is intentionally honest synchronous prototype behavior, not a claimed asynchronous, lock-free 4K save. PSD encoding and current verification can allocate additional bounded buffers. Recovery stores native source without relying on GPU lifetime. Recovery generations are not auto-pruned yet; `.ylp` backups are pruned only to the count the user chose (default: keep all).

## Project resources

A project holds resources (`Core.Shelf.ProjectResources`, the window's `ImageResources`): images shared by every texture set, each with a stable ID, a name, an embedded copy of its pixels (`ImageContent`: straight RGBA8, 1–8192 per side, never changed once made, named by the SHA-256 of its size and pixels) and where it came from (`ResourceOrigin`: a Unity asset by GUID with Unity's dependency hash as a quick stamp, a file by path and SHA-256, a file in the user's library folder, a built-in image by key and version, or nothing). Equal pixels are held once and the budget (personal settings, automatic: 1/16 of the machine's memory, 256 MiB–4 GiB) counts each content once; refused additions change nothing. Resource changes are project-level like the texture-set list: unsaved, not in a document's undo history, removal asks first and is refused while a usage probe names a user. Consumers look images up through `IImageResources` and follow `Changed` / `Revision`: today fill layers' images (below; decals and the mask's image stage are to come).

Unity assets are only read. A Texture2D readable on the CPU is read with `GetPixels32`; any other is drawn into a same-size temporary ARGB32 render texture whose sRGB flag matches the texture's sampling, and read back with `ReadPixels`, so the stored values come back in gamma and linear colour-space projects alike (tested for every 8-bit value, both texture kinds, both spaces, by switching the test project's Player colour space for the test). Compressed textures give the values the GPU decodes; HDR and non-2D textures are refused. The readback is checked once per session on known texels and refused with the reason where it does not reproduce them. Nothing is applied, made readable or re-imported, and the tests compare the source file, its .meta, the importer's serialized settings, Unity's dependency hash and the loaded texture's dirty/readable state before and after.

A changed source is detected by its stamp, then confirmed by reading the pixels again and comparing content hashes (a change of import settings alone that leaves the pixels equal is not a change). The copy is never replaced automatically: opening a project asks, the Assets panel shows a notice with Update / Keep, and a source that is gone leaves the copy in use. Placing a resource makes one paint layer in the current channel above the selected layer, the image fitted to the texture set with the canvas resampler's formulas (`ImageResampling`), in one `Batch` (one undo step), without touching the selection.

## Fill images and projection

A fill layer's channel can read a project image (a resource ID) instead of its one value, and each fill layer has a projection (Substance Painter's fill Projection): UV (tiles, offset, rotation; repeat or clamp), tri-planar (blend width), planar, spherical and cylindrical. The model projections read the baked Position map (and, for tri-planar, the world normal) through the same inputs as generators (`IGeneratorInputs`, `IGeneratorModelFrame`: the model root's position and rotation, scene units), and pass the channel's value through with a reason while a map is missing, stale or of another size; their placement box is moved in the 3D view with the shape gradient's gizmo (`ShapeGizmo`; the window edits either a shape gradient or a projection). Each document holds the project's resources as `PaintDocument.ImageResources` (the window connects every texture set) and resolves IDs again when the resources' revision changes, so updating a resource from its source, changing its colour space or connecting other resources redraws the layers that read it; the window's usage probe names those layers, so an image in use cannot be removed. An ID the resources do not have shows the value with a reason and is kept (opening such a project is not refused; the window lists them).

Values: data channels (Roughness, Metallic, Height, Normal) use the image's stored values whatever its colour space, as Substance Painter does (a data image imported into Unity as sRGB keeps its stored values, which a Unity material sampling that texture would linearize); colour channels (Color, Emission) encode a linear (data) image to sRGB; scalar channels take the luminance. Pixels are evaluated deterministically on the CPU (mipmaps with trilinear sampling for minified pixels, the footprint from the UV transform or the neighbouring texels' points on the model; no anisotropic filtering) through the filter engine's evaluated-output path (`PaintLayer.HasEvaluatedOutput`), so both display compositors and every export read the same cached bytes; see `Runtime/Core/README.md`. A request to the filter engine evaluates at most twice the worker count of nearby stale blocks, so the display's time-sliced compositing (`CompositeSchedule`) can stop between blocks (filters and generators share this; a whole-layer re-evaluation is a little slower than one batch of everything). Native version 16 stores the IDs and the projection; the pixels stay in the .ylp's resources (format 4 unchanged). PSD export writes a projected channel as a raster layer and reports what it does not carry.

## Canvas size

A texture set's size is changed from Project Configuration (one size per set, the New Project sizes 512–8192 squared). The window asks first, then builds a resampled copy of each resized set's document (`PaintDocument.Resampled`, see `Runtime/Core/README.md`) before changing anything else; a copy that would exceed the project-wide layer pixel budget (the settings' budget minus the sets that stay) or a filter limit is refused and nothing changes. The copies then replace the documents: paths on the model are drawn again with the loaded model (or kept as resampled pixels with a note), the set's undo history is gone (the copy has none; other sets keep theirs), and displays, thumbnails, the compositor and the other sets' previews rebuild because the document object changed. Resizing is deliberately not an undo step: undo would have to keep every old pixel next to the new ones (a quarter more when the size doubles, four times more when it halves), beyond the undo budget because the newest steps are always kept, and every older history entry refers to surfaces of the old size. Baked mesh maps are kept and report stale (their provenance records the size). The .ylp format is unchanged.

## PSD boundary

The custom codec is deliberately small and bounded, and has no external runtime package. Its DTO pixels are top-down, so `PsdBridge` explicitly flips rows. Supported raster PSD export is an explicit command, separate from saving the `.ylp`; if metadata/blend/mode cannot be represented safely, PSD projection stops and nothing is written. Off-canvas PSD layers are rejected at native import because native v1 lacks off-canvas sparse tiles. Original supported-import bytes are kept as a separate entry (`imported-original.psd`) inside the `.ylp`. The codec does not read linked resources, execute embedded payloads or launch external applications.

The public PSD mode is not an external-application certification. See PSD_COMPATIBILITY.md for structural acceptance, original-byte preservation and image fidelity evidence.

## Remaining architecture

Typed DAG validation currently covers stable node identity, type/semantic compatibility, same Texture Set, layer/effect order and cycle prevention. This is executable validation code, not an implemented material graph editor. Generators (`Runtime/Core/Generators.cs`) are point stages of the same effect stack as filters: each reads the mesh maps of its texture set through `IGeneratorInputs` (set per texture set by the window; only maps `MeshMapSet.TryGetUsable` accepts for the current model, high-poly, bake settings, size and slot), snapshots them when the inputs' revision changes, and passes its input through with a reason when a map is missing, stale or of another size. Documents poll the inputs only at `TryGetChangedTiles`, the compositor entry points, stack edits/undo and baking, never per tile; a changed map bumps the generator stamp and marks only layers with generators changed. Generators are evaluated on the CPU only (the GPU path uploads evaluated tiles). The ID colour generator (type 6) reads the ID map and gives 1 where a texel's colour is within its tolerance of one of its colours. The shape gradient (type 5, `ShapeVolume`) reads the Position map back into the snapshot space with its provenance's bounding box and then into the model root's space with the frame the inputs give (`IGeneratorModelFrame`: the loaded root's position and rotation; identity for inputs that do not say), so a box, sphere or plane placed relative to the root stays on the model when the root is turned and the maps are baked again; the window edits it with a gizmo in the 3D view and can copy a scene object's BoxCollider, SphereCollider or transform relative to the root (read only). Still missing before claiming Anchor support: anchor-stage outputs as generator inputs, neighbourhood (halo) generators such as curvature from painted height, evaluation scheduling through the DAG, and stale revisions across texture sets.

## 指先・クローン・ぼかしのブラシ

`BrushSettings.Effect`（既定は Paint）は `BrushStroke.Effects.cs` で既存ストロークのターゲット・被覆率・巻き戻しを使う。
ダブが触れる参照領域を全チャンネルで書き込み前に凍結し、ワーカーはその写しだけを読む。参照領域と積分表は
`ActiveStrokeBudgetBytes` に含め、拒否と例外は全チャンネルを取り消す。Undo は結果のタイルを戻し、再演算しない。

- ぼかし: 半径 1〜64 画素の箱型の平均。RGB はアルファを重みにし、アルファは窓内の平均。
  整数の積分表で窓の和を求め、画像の外は窓から除く。ストローク前にアルファが 0 の画素は RGB・アルファとも変えない。
- 指先: 最初のダブは拾うだけ。次のダブでは前のダブ中心への相対位置で、現在の画素をプリマルチプライドで補間して拾う。
  引きずる量は流量に掛ける。同じ位置のダブは何もしない。透明な場所へ色を引き出せるが、結果のアルファが 0 なら元の RGB を保つ。
- クローン: ストローク前の現在のレイヤーかマスクを相対位置で拾い、通常ブラシの source-over で描く。
  既に触った読み元のタイルは巻き戻しの写しを使い、同じストロークで描いた画素を再度写さない。
  参照が画像の外なら描かず、整数の相対位置では標本をそのまま拾う。合成結果の参照は未対応。

効果はダブごとに変わる標本と蓄積した被覆率を使い、元の画素から計算し直すので、不透明度・筆圧の天井と
選択範囲の割合を守る。ぼかしと指先は元と標本のプリマルチプライド補間、透明部分のロック時はアルファを固定して色だけを寄せる。
効果では描画色・マテリアルの値・カラーダイナミクスを使わず、各チャンネルの画素を別に計算する。マスクでは格納された隠す量に効く。
選択量は書き込みにだけ掛け、近傍や写し元は選択範囲の外からも読む。

窓では別ツール（S: コピースタンプ、U: ぼかし、Shift+U: 指先）で、R の表示回転を残す。
Alt＋クリックで写し元を画素の中心に置く。位置合わせがオンなら確定したストロークの相対位置を次も使い、オフなら毎回写し元から始める。
取消で相対位置を確定させない。写し元はレイヤー・マスク・文書・大きさに紐付く一時状態で、保存・リロードで引き継がない。
`brush.json` とプリセットの schema 3 に半径・引きずる量・位置合わせを追加し、置き場の schema 2 に Core の効果設定を追加した。
正本の画素と形式は従来のまま。古い JSON は既定値で読む。ツールの列挙値は末尾に追加し、既存ツールの値を保つ。
筆先のプリセットを選ぶときは現在のツール・ぼかしの半径・引きずる量・位置合わせを保つ。保存した JSON プリセットの読み込みでは効果の値も復元する。

3D はダブ全体を `ApplyDab` に渡し、全画素の読み元を凍結してから適用する。ぼかしは UV 空間の近傍、指先は UV 空間の移動を使う。
指先は UV アイランドが変われば拾い直し、鏡映の対称との同時利用は理由を表示して断る。表面に沿った距離・方向や
継ぎ目を跨いだ画素輸送、モデル上の鏡像ごとの指先方向は保証しない。3D のクローンは継ぎ目を跨ぐ写し元を相対 UV だけで
一意に指定できないため、理由を表示して断る。Photoshop と CLIP STUDIO の実機との画素一致は未検証。
