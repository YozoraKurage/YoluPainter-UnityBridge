# Unity テクスチャペイント拡張 仕様書

版 0.1　2026年10月2日　仕様策定用

Unity Editor内の専用ウィンドウで、モデルへ直接描き、UV上で細部を整え、レイヤーをPSDとして扱える制作環境を設計する。Substance 3D Painterのマルチチャンネル制作と編集可能な3Dパス、CLIP STUDIO PAINTの描きやすさを両立させることを目標とする。本書は実装前の機能契約と技術設計であり、実装済み機能や性能測定結果を示すものではない。

## 設計の結論

- 描画中の正本は専用ドキュメントモデルと差分タイル。PSDはラスターレイヤーの永続化、独自プロジェクトは3Dパス・チャンネル・モデル対応などPSDで表せない情報の永続化を担う。
- GPUのブラシ描画と合成、CPUのBurstとJobsによる適切な幾何処理、バックグラウンドのPSD入出力を組み合わせる。4K全レイヤーを常時GPUに置く設計は採用しない。
- 広いPSD互換を目標にしつつ、編集・保持・表示再現・検証済み範囲を分ける。未対応データを黙って破棄したり、見た目が違うまま元PSDへ保存したりしない。
- 低スペックでも作業を継続できることを設計要件とする。32 GB RAM／8 GB VRAMは参考試験条件であり、最低要件ではない。

## 決定状態の読み方

| 区分 | 意味 |
| --- | --- |
| 確定要望 | 専用ウィンドウ、2Dと3Dの連動、初期lilToon、ポーズとBlendShape、PSDレイヤー、調整レイヤー編集、3Dパス、マルチチャンネル、Generator・Filter・Anchor・Mask、継ぎ目・対称・裏面貫通防止、外部PSD変更検知 |
| 採用案 | タイル方式、CPUとGPUの分担、複数PSDの保存構成、互換モード、保存世代管理、Undo方式。本書で具体案を選び、技術検証で確定する |
| 未決事項 | 対象UnityとOS、対応ペンタブ、厳密なPSD対応種類、重複UVの制作方針、UDIM・HDR・最大サイズ、配布形態 |

優先度と開発段階は実装の順序を表し、最終的な機能範囲を黙って削るためには用いない。互換性と低スペック性能は、機能追加後の最適化ではなく初期の検証ゲートに置く。

# 1 制作フローと画面構成

## 基本フロー

- プロジェクトを作成し、モデル、材質スロット、対象UVセット、解像度、利用チャンネルを登録する。読み込み診断でUV欠落、重複UV、極端な歪み、素材と色設定の不一致を表示する。
- モデルの複製を隔離プレビューへ配置する。ユーザーはポーズやBlendShapeを変え、照明付き材質表示と照明を含まないチャンネル表示を切り替える。
- 3D表面で大まかに描き、同じレイヤーとチャンネルを2Dキャンバスで微調整する。選択、マスク、クリッピング、調整レイヤー、パスを併用する。
- 明示保存でPSDとプロジェクトの同一世代を確定する。必要時のみ材質用テクスチャを書き出し、指定されたUnity材質へ適用する。外部PSDの編集は変更通知から取り込む。

## 専用ウィンドウの構成

| 領域 | 主要な操作 |
| --- | --- |
| 中央 2D／3D | 並列・単独表示、ズーム、パン、回転、UV表示、チャンネル単独表示、筆先と対称のプレビュー |
| 左 ツール | ブラシ、消しゴム、選択、塗りつぶし、グラデーション、スポイト、変形、定規、パス |
| 右 レイヤー | グループ、チャンネル有効化、マスク、合成、不透明度、ロック、調整、互換状態 |
| 補助パネル | ブラシ設定、色相環・パレット、材質とUV、ポーズとBlendShape、履歴、保存状況、性能診断 |
| 状態表示 | 解像度、対象材質、メモリ圧迫、プレビュー品質、外部変更、未対応PSD情報、保存世代 |

## 操作の分離

描画・モデル操作・ポーズ編集・パス編集を明確なモードに分ける。筆圧入力中にカメラ操作へ誤遷移しない。ショートカットはウィンドウのフォーカス中だけ扱い、Sceneビューへの入力漏れを防ぐ。フォーカス喪失、ペン離脱、例外時にはストロークを確定または取消し、入力状態を残さない。

モデル・材質・アニメーションの編集はプレビュー用の管理オブジェクトだけに適用する。任意のPrefabをそのまま生成するとExecuteAlways等が先に動く可能性があるため、対応するRenderer・骨・Transformのみを抽出して再構成する。[U3][U3a] シーン材質や元テクスチャへの反映は別コマンドとする。隔離ウィンドウだけでは共有GPU負荷、Editorの静的状態、他拡張のコールバックまで分離できないため、非干渉は試験で確認する。

## レイヤーの意味を固定する

描画レイヤーはピクセル正本、パスレイヤーは編集可能なパス正本、調整レイヤーはパラメータ正本とする。パスをラスタライズする操作は明示的な変換とし、元パスを残す選択肢を出す。ブラシの混色が下位合成を参照するときは参照時点を確定し、再合成によって描画結果が勝手に変わらないようにする。

## 広い機能範囲と段階的な完成

P1だけを完成品と定義しない。直線・図形・Bezier、制御点・線幅の再編集、線の分割／結合／単純化も機能検討表に残す。2Dベクター、描画を誘導する定規、表面3Dパスは別の型である。全ツールを全レイヤー型へ使えるとは仮定しない。[C1][C3]

ブラシと設定は独自形式で保存・読込する。CSP独自ブラシの.sutやCSP独自文書の互換は未確認であり、自動対応を約束しない。素材塗りつぶし、マスク効果、ジェネレーター、フィルター、アンカーとmesh map入力は中核範囲に含め、第5・6章で定義する。Painter全機能や独自資産形式の互換を自動的に意味するものではない。

# 4 チャンネルとlilToonへの出力

意味上のチャンネルとシェーダーのプロパティを切り離す。1回のストロークは複数チャンネルを有効化でき、チャンネルごとに値、筆先、強度、合成方式を持つ。カラーだけを消す、粗さだけを塗る、といった編集を他チャンネルに波及させない。

| チャンネル | 内部の意味 | 初期lilToonアダプターの方針 [L1] |
| --- | --- | --- |
| Color／Opacity | 色と被覆率。色はプロファイル、アルファは線形量として区別 | _MainTexと_Colorへ接続。透過モード、カットアウト、材質色乗算も別設定 |
| Roughness | 0は滑らか、1は粗いという意味で統一 | _SmoothnessTex.rと_Smoothnessへ変換。_UseReflection等の有効条件を検証 |
| Metallic | 金属度のスカラー | _MetallicGlossMap.r × _Metallic。Standard shaderのalphaへのSmoothness格納を流用しない |
| Height | 高さのスカラーと単位／基準値 | _ParallaxMap、_UseParallax、_UsePOM等を版とvariantで確認。Parallaxは形状変位と区別 |
| Normal | 接空間の法線。符号、Y方向、強度、合成式を保持 | _BumpMap、_UseBumpMap、_BumpScale。専用合成後に正規化しUnityの法線表現へ変換 |
| Emission | 発光の色と必要に応じた強度 | 発光テクスチャと色／強度へ接続。HDR強度をPSDの通常色だけに押し込まない |

## アダプターの契約

対応lilToonバージョンとレンダーパイプラインを固定したマニフェストを作り、プロパティ名、キーワード、利用可能な機能、チャンネルのパッキング、スケール、色空間、書き出し形式を定義する。起動時に対象材質を検査し、不一致は警告または接続停止とする。名前が似た別シェーダーへ自動適用しない。[L1]

プレビュー材質にはメモリ上のRenderTextureを接続する。最終出力用のPNG等やUnityインポート設定の更新は、明示書き出し時または明示的な同期時だけ行う。メインテクスチャを毎ストローク保存・再インポートする方式は採用しない。

Heightから生成するNormalは派生結果であり、手描きNormalと区別して重ねる。Roughnessの1−r変換は対応するperceptual roughness規約に限る。変換は値域の対応であって、PainterとlilToonの材質表現の完全一致を意味しない。照明付き表示とチャンネルのフラット表示を必ず用意する。

# 5 塗りレイヤーと手続き効果スタック

ジェネレーター、フィルター、アンカー、マスクはSubstance型の制作に必要な中核機能として対象に含める。Paint、Fill、Pathのソースと、非破壊の効果スタックを分け、結果をあとから変更できるようにする。PSDの画像レイヤーだけでは保存できない意味は独自プロジェクトへ保存する。[A6][A7][A9]

| 要素 | 編集契約と入力 |
| --- | --- |
| PaintとPath | Paintは確定画素、Pathは曲線とブラシ設定をソースとする。破壊的な画素編集と非破壊効果をUIで区別 |
| Fillレイヤー | チャンネルごとの一定値・色・画像・手続き入力を保持。UV変換、強度、チャンネル有効化を編集し、結果を再評価 |
| ラスターマスク | 0〜1の被覆率を手描き・消去・選択・塗りつぶしで編集。階層、リンク、無効化、反転、濃度を保持 |
| マスク効果スタック | 描画、Fill、Generator、Filterを順序付きノードとして重ねる。ノードの有効化、値、合成、強度、マスクを編集 |
| フィルター | ぼかし、シャープ化、レベル／レンジ、反転、変形、HeightからNormal等。入力型と出力型、局所性、精度を宣言 |
| ジェネレーター | mesh map、画像、アンカー出力、パラメータから色／マスク等を生成。汚れ、エッジ摩耗、空間勾配、ノイズ等を内蔵候補とする |
| プリセット | 効果の構成、パラメータ、資産と版、乱数シードを保存。欠落資産を検出し、暗黙の代用品で確定しない |

## 効果の順序と適用範囲

効果ごとに安定UUID、アルゴリズム版、入力チャンネル、出力型、パラメータ、資産参照を持つ。順序変更はプレビューとUndoを伴う。Color用の色相調整をRoughnessへ誤適用しない。無効な型接続は作成時に拒否する。マスクへの効果とレイヤー画素への効果は表示を分ける。

均一Fillは全画素を事前確保せず、値と領域を正本としてタイル生成する。局所フィルターは必要なhaloを含むタイル、全体統計を使う効果は文書範囲を処理する。Generatorの複雑さや順序に応じて再評価費用を見積り、表示用の近似結果と確定結果を区別する。

## 互換性の境界

この仕様は制作概念の対応を定める。Substanceの.SBSAR／.SPSMや外部スマートマテリアルをそのまま実行・読込できるとは約束しない。内蔵効果と独自プリセットを先行し、外部資産形式の利用はランタイム、SDK、ライセンスと結果再現を別途検証する。CSPの調整、PSDネイティブ調整、独自Filterは同名でも同一形式と扱わない。

# 6 アンカーとmesh mapの依存管理

## アンカーの参照契約

アンカーは選択したノードの出力を他のレイヤーや効果から参照する名前付き接続点である。Anchor UUID、Texture Set UUID、Content／Mask、効果位置のUUID、出力型とrevisionを保存する。参照側は取得チャンネル、入力への割当、alphaの扱いを持つ。名前変更で参照を壊さない。取得対象はアンカーを置いた効果位置の出力であり、最終レイヤー全体とは限らない。マスクは0〜1のスカラーとする。[A8][A8a]

初期採用案は同一Texture Set内の下位レイヤー、または同一スタックの先行出力だけを参照可能にする。レイヤー階層の依存と合わせたDAGで、自己参照、間接循環、無効なチャンネル型を接続前に拒否する。並べ替えで規則に違反する場合も確認前に変更を確定しない。参照先を削除するときは利用箇所を表示し、別ソースへ接続、明示的な固定化、削除取消しを選ぶ。欠落を無言で黒として続行しない。

## 変更の伝播

ソースの画素、マスク、パラメータ、資産が変わるとAnchorのrevisionが進み、利用ノードと上位合成だけを無効化する。局所効果はdirty領域とhalo、非局所効果は必要範囲全体へ展開する。UIで非表示でも参照に必要なノードは評価対象に残す。評価世代を揃え、古いアンカー結果と新しい画素を混ぜて保存しない。

例として、手描きHeightをアンカーへ公開し、局所的な法線／曲率を派生させ、エッジ摩耗Generatorのマスクへ接続する。元モデルから焼いた曲率mapが、手描きHeightに自動追従するとは扱わない。どの曲率を参照するかをノードとUIで明示する。

## ベイク入力と無効化

自己ベイクと参照メッシュからのベイクを区別し、cage、前後のray距離、出力対象とログを管理する。採用するベイク方式と対応形状はG0で検証し、失敗したmapを正常として使わない。[A10]

| 記録する由来 | 再評価の条件 |
| --- | --- |
| モデルとUV | 元アセットhash、トポロジー、UV、材質、ベイク解像度。変更で関連mapとGeneratorを無効化 |
| 基準ポーズと空間 | Object／World／Tangent等と基準ポーズを記録。基準ポーズベイクは表示用ポーズ変更で自動再ベイクしない |
| 設定と品質 | AO、曲率、Position、Normal等の種類、距離・範囲、精度、エンジン版、必要ならcage／参照メッシュを保存 |
| 依存変更 | ベイク設定・基準形状・外部map更新を検知。再ベイク中、旧結果、確定結果を区別し取消し可能にする |

ベイク条件が異なる結果を同じキャッシュとして再利用しない。プロジェクトは効果グラフ、アンカー、map由来、資産を正本として保持する。PSDへは評価済みラスタと検証済みのネイティブ調整を投影し、手続きグラフをPSDだけから再構成できるとはしない。外部が生成画素を変えたら、後続章の正本選択と競合処理を適用する。

# 7 PSD互換性の契約

「PSD対応」を単一の可否では表さない。Adobeの公開形式仕様は構造を示すもので、すべての描画解釈を定義してはいない。各機能にE 編集、P 原情報の保持、R 表示再現、T 検証済み条件の4項目を記録する。以下は目標と制約であり、Tは本拡張について全項目未実装・未検証である。[P1]

| PSD要素 | E 編集 | P 保持 | R 表示と主要条件 |
| --- | --- | --- | --- |
| ラスターレイヤー | 対象 | 対象 | チャンネル、アルファ、位置、ビット深度、圧縮方式ごとに検証 |
| 階層と属性 | 対象 | 対象 | 順序、名前、可視性、不透明度、塗り、ロックを区別 |
| マスク／クリッピング | 対象 | 対象 | 密度、ぼかし、相対位置、連鎖、グループ合成を検証 |
| 通常と各合成モード | 型別に対象 | 対象 | 合成色空間、ガンマ、丸め、アルファ処理で差が出る |
| 調整レイヤー | 型別に対象 | 対象 | 読めるパラメータだけで同じ演算になるとは限らない |
| テキスト | 編集対象外 | 非破壊保持を目標 | 元の描画キャッシュがあれば利用。フォント・縦書き・ワープ等の再組版はしない |
| スマートオブジェクト | 編集対象外 | 非破壊保持を目標 | 埋込／リンク、依存ファイル、変形、フィルターとキャッシュを別に保護 |
| 効果／Blend If等 | 未確定の型は読取専用 | 非破壊保持を目標 | 描画エンジン未対応なら合成一致を保証しない |
| 未知の追加情報 | 編集不可 | 原バイト保存を試験 | 保持できても、依存する他要素の変更が安全とは限らない |
| ICC／特殊色モード | 対象範囲を要決定 | 元情報を保存 | RGB以外、32-bit、特殊プロファイルは入口で判定 |
| PSD／PSBサイズ | PSDを優先 | 対応形式ごとに検証 | PSDは寸法などの制約を診断。巨大書類のPSB対応は別ゲート |

## 表示不能と保持不能は別の停止理由

合成に寄与する要素を再計算できない場合、単純に元の合成画像を背景として置けば編集互換になるわけではない。その要素を含む文書は安全な読取専用表示、対象部分の固定化を了承した別名保存、または対応実装まで編集停止から選ぶ。未対応情報がある元PSDへの通常上書きは許可しない。

# 8 PSDの保持と表示再現の実装方針

## 入出力層に求める機能

PSDコーデックはメタデータ解析とピクセルの遅延読込を分離し、未知ブロックを含む元情報、レイヤーID、元順序、長さ、形式バージョンを保持する。合成画像が存在しないPSDも診断する。未編集ブロックは可能な範囲でパススルーし、変更された構造に依存するオフセットや長さは再構築する。「原バイト保持」をファイル全体のバイト一致と混同しない。[P1]

ライブラリはライセンス、商用配布可否、16-bit、PSB、追加レイヤー情報、マスク、調整、スマートオブジェクト、未知ブロックの往復、スレッド安全性を実物で検証して選定する。Unity標準のPSD取込機能が、この拡張の完全なPSD編集・保存コーデックになるとは仮定しない。

## 互換プロファイル

| プロファイル | 動作 |
| --- | --- |
| Native Paint | 本拡張の色・合成規則で編集する。PSDへ表現可能な範囲はそのまま保存し、派生要素には対応情報を添える |
| PSD Compatible | 元PSDの合成規則に寄せる。対応済みの色モード、ビット深度、合成と調整の組合せだけを編集可能にする |
| Preserve Only | 未知・未対応要素を破壊せず保持し、必要に応じて元の合成プレビューを提示する。安全に更新できない操作は止める |

## 調整レイヤーの受入単位

調整を一括して「対応」としない。各型について、パラメータ読込、UI編集、Unity上の再合成、PSDへ書戻し、外部アプリで再表示、再取込の6工程を検証する。レベル補正とカーブ等を先行しても、他の要望を対応済みと扱わない。露光量、白黒、写真フィルター、チャンネルミキサー、Color Lookup、特定色域の選択、反転、ポスタリゼーション、2値化、自然な彩度も型別の対象表に残す。単色・パターン・グラデーションの塗りノードは調整と分ける。グループ・マスク・クリッピングを組み合わせて試験する。[P2]

## 保存時の診断

- 編集可能性と表示信頼度をレイヤーごとに表示し、文書全体にも最も厳しい状態を表示する。
- 未対応ブロックの消失、更新不能なキャッシュ、リンク切れ、フォント不在、合成差分を保存前に報告する。
- 無変更の開閉保存、対応要素だけの編集、未対応要素の隣への追加を別々に試験する。原本を残し、確認済みの別名出力から往復試験を始める。リンク資産は欠落を検知し、ネットワーク取得・外部アプリ起動・無制限再帰をしない。

# 9 プロジェクトのデータモデル

採用案は、PSD群と独自プロジェクトを同じ制作単位として扱うフォルダー形式である。独自プロジェクトの拡張子は未決定。SPPに似た編集状態の保存を目指すが、AdobeのSPP形式との互換は要求していない。

| データ | 正本と識別子 | 保存内容 |
| --- | --- | --- |
| Project | Project ID／Schema version | 保存世代、形式バージョン、色設定、作業解像度、参照パス、必要機能 |
| Texture Set | Texture Set ID | モデル、材質スロット、UVセット、解像度、必要チャンネル、lilToon出力設定 |
| Semantic Layer | Layer UUID | 階層、チャンネル有効化、合成、マスク、クリッピング、PSD内IDとの対応 |
| Raster Source | レイヤーとチャンネル | PSDに保存される画素。内部作業時はタイル表現。PSDの階層・属性との対応規則を定義 |
| Path Source | Path UUID | 表面制御点、補間、筆先、幅、圧力、チャンネル、乱数シード、生成版 |
| Model Binding | モデル指紋とBinding ID | アセット参照、サブメッシュ、三角形、頂点／UV情報の指紋、パス再結合状態 |
| Effect Graph | Node／Anchor UUID | 順序、型、入力、パラメータ、アンカー出力段階、mesh map由来、資産、評価版 |
| Brush and View | Preset ID／View State | ブラシ設定、定規、対称、ポーズ、BlendShape、ビュー、非破壊編集パラメータ |
| Derived Cache | ソースhash／engine version | 合成タイル、パスのラスタ結果、サムネイル、法線生成。削除して再生成可能 |

## マルチチャンネルPSDの配置

最初の採用案はTexture Setごと・チャンネルごとのPSDとし、意味上のレイヤーUUIDで対応づける。ColorはRGBA、スカラーデータは選定したPSD表現で格納する。単一PSDのRGBへ無関係なデータを無説明に詰め込まない。各PSDのレイヤーIDだけに依存せず、ID消失や複製に備える。

意味上の共通構造はプロジェクトが管理し、受理したPSD変更を操作として取り込む。PSD属性とプロジェクト属性が同時に競合する正本にならないよう、各項目の所有者を定める。パス由来の画素は生成キャッシュであり、パスと両方を正本にしない。外部アプリが生成レイヤーを変更した場合は、別ラスターレイヤーへ取り込む、パスの生成結果を固定化する、外部編集を取り消して再生成する、の選択を要求する。外部PSDでの階層変更を全チャンネルへ自動波及するかは、ID照合と明示的な同期規則で決める。

# 10 保存と外部編集の整合性

## 作業中と明示保存

ストロークごとに巨大PSDを再構築しない。作業中は差分タイルと操作ジャーナルを更新し、一定間隔または重要操作後にバージョン付きの復旧スナップショットを作る。保存開始時点の不変スナップショットを固定し、その後の入力は次世代へ分離する。対象GPUタイルはpinまたはcopy-on-writeで守り、copy／readback完了前に上書き・再利用しない。revision番号だけで不変性が成立するとはしない。保存中の入力を止める必要がある場合は理由と進捗を表示する。

## 複数ファイルのコミット

- 新しいrevisionのステージング領域へ、対象PSD、プロジェクト、チェックサム付きマニフェストを書き出す。出力を閉じ、再読込または検証で整合性を確認する。
- 保存先の外部revisionを置換直前にも再確認し、不一致なら中断する。flushの対象とOSの保証を検証して「準備済み」をジャーナルに記録する。同一ファイルシステム上のrename／replace能力を確認し、プロジェクトが参照するcurrent世代を最後に切り替える。
- 複数PSDを1回の原子操作で同時置換できるとは仮定しない。正本は完全なrevision集合とし、平坦な外部編集用コピーを用意する場合は同期状態を別管理する。
- 失敗時は旧currentを保ち、次回起動で完成済み世代のみ採用する。ディスク不足、権限、ロック、停止、クラッシュの各中断点で試験する。

## 外部PSDの変更

ファイル監視は変更の合図として使い、デバウンス後にサイズ・時刻・内容hashを確認する。保存途中のファイルをすぐ読み込まず、安定化待ちと読込再試行を行う。本拡張自身の書出しは世代とhashで識別する。監視イベントの欠落に備え、フォーカス復帰時と保存前にも再確認する。

| 状態 | 取り込み方針 |
| --- | --- |
| ローカル未変更 | 外部版を診断し、差分内容を表示して再読込。表示や選択はIDで復元 |
| ローカル変更あり | 競合ダイアログを出し、両方のスナップショットを残す。再読込・別名保存・取消しから選択 |
| パス生成レイヤーが変更 | 正本を選ぶ専用確認を出す。パスと外部画素を無言で上書きし合わない |
| ID消失／階層変更 | 名前だけで自動結合しない。対応候補と差分を示し、曖昧な対応は保留 |

プロジェクトだけ保存できた場合は「プロジェクト保存済み・PSD未更新」と分けて表示する。受理した再読込は1操作としてUndo可能にする。レイヤー単位の三者マージは将来検証項目とする。PSDの匿名化ID、グループ合成、マスク連動を考えると、一般的な無損失マージを現段階では約束できない。

# 11 Unity上の責務とAPIの対応

対象Unityバージョンは未選定。以下はUnity 2022.3等の公式APIで成立を確認できる候補であり、古い版や最新の全版への互換保証ではない。対象版、レンダーパイプライン、OS、Graphics APIを技術検証の開始時に固定する。

| 責務 | 採用する仕組み | 実行場所と制約 |
| --- | --- | --- |
| UIと入力 | EditorWindow、UI Toolkit、Pointerイベント、必要時IMGUI | メインスレッド。圧力／傾きなどは実機とイベント経路を検証 [U1][U2] |
| 隔離プレビュー | Preview Scene／PreviewRenderUtility、複製モデル・材質 | 専用カメラと照明、既定シーンへ書込まない。共有資源まで隔離しない [U3] |
| ブラシ描画 | RenderTexture、CommandBuffer等によるGPUラスタスタンプ | ストローク順序、ブレンド、対象タイル、GPU資源寿命を一元管理 [U4] |
| 合成とフィルター | ComputeShader、対応formatのRWTexture、必要時ラスタ代替 | ランダム書込・format・API対応を起動時判定。GPUの順序と依存関係を管理 [U5] |
| 幾何計算 | Jobs／Burst、NativeArray、MeshData系API | BVH、対称対応、ストローク補間などのplain data。Unity Object操作をJobに入れない [U6] |
| 転送と書き出し | AsyncGPUReadback、非同期I/O、検証済みPSD codec | 待ち時間と一時メモリを予算化。同期ReadPixelsを描画経路に置かない [U7] |
| 変形スナップショット | SkinnedMeshRenderer.BakeMesh等 | BakeMeshはCPU skinning。ポーズ変化時にまとめ、毎入力呼出しを避ける [U8] |
| 資源と再読込 | AssemblyReloadEvents等のEditorライフサイクル | Job完了、GPU処理と読戻しの安全な終了、RT／Native資源解放 [U9] |

## CPUとGPUを混同しない

Burstは対応するC#処理をCPU向けネイティブコードへコンパイルする仕組みであり、GPU化でも万能な高速化でもない。画素数の多い合成はGPUを優先し、幾何・インデックス・圧縮前処理などにCPU並列化を使う。PSDの可変長構造やマネージドライブラリ全体をBurstへ移す前提は置かない。

Unity APIのスレッド制約は個別確認する。例として2022.3のEncodeNativeArrayToPNGにはメインスレッド限定の注意がある。8-bit PNGの背景保存は、所有するCPU配列へ転送後、スレッド安全性が記載されたEncodeArrayToPNGを候補とする。コピー費用を予算化し、ICCや高bit出力は別の適切なcodecを選ぶ。[U10][U10a]

# 12 表面描画とUV継ぎ目

## 入力からタイル更新まで

- 画面座標、入力時刻、筆圧、傾き、ツール設定をストロークサンプルとして記録する。補正前の入力と補正後の点列を区別する。
- 現在の変形スナップショットに対し、CPU BVHまたはGPUのID・深度でヒット候補を取得する。可視面、材質、選択、マスクを絞り込む。
- 三角形と重心座標を得て、固定されたトポロジーのUVへ写す。ブラシの表面上の広がりを、影響する隣接三角形に展開し、各三角形をUV空間へ投影してタイルを更新する。
- ブラシ半径、間隔、筆圧の補間を統一し、UV歪みと画面拡大率が極端なときのサンプル不足を診断する。変更領域のみ合成し、2Dと3Dへ同じ結果を表示する。

## 継ぎ目を越える条件

UV上で離れた島でも、実表面で隣接する三角形には同じ世界空間の筆跡が届くようにする。継ぎ目はメッシュの隣接関係、必要時の位置一致、サブメッシュ境界の方針から作る。UV画像の近い画素へ単純に横断する方法は使わない。縫合された別頂点、重複頂点、ハードエッジ、非多様体を区別する。

テクスチャ境界のpadding／dilationは、描画そのものとは別処理にする。島IDと有効領域に従って余白を拡張し、隣の島の本体を汚さない。mipmapやフィルタリングで必要な幅を解像度と用途から決め、局所更新できる依存領域を持つ。

## 裏面と隠れた面への貫通防止

ブラシ球の内部にある全三角形を塗るだけでは、胴体の裏、指の反対側、重なった服まで汚れる。表向き法線判定に加え、カメラの深度・ID、ヒット面への連結性、奥行き許容値を組み合わせる。薄い板や折れ目も試験する。可視面以外も塗る機能は明示モードにし、既定で無効にする。

## 対称と重複UV

3D対称はObjectまたはWorldの基準面を指定し、対称位置で表面を再ヒットする。UV左右対称を仮定しない。対称ストローク同士が同じ画素へ届く場合の二重加算を防ぎ、対称先が見つからない場合は表示する。

同じテクスチャ座標を共有する面は同じ画素を読む。面の選択やヒット制限だけでは、最終材質で別々の色にできない。既定案は警告して対象面を選ばせ、共有結果もプレビューする。独立した結果が必要ならUV展開の変更、別Texture Set、別材質などの制作変更が必要であり、方式は未決定とする。

# 13 変形したモデルと編集可能な3Dパス

## ポーズとBlendShape

元モデルを変更せず、プレビュー複製の骨とBlendShapeを操作する。変形後表面でヒット判定しても、描画先は対応する静的UVである。三角形IDと重心座標を軸に、変形前後の対応を保つ。ポーズ更新をまとめてBakeMesh等のスナップショットを更新し、BVHの再構築／refitの費用を比較する。[U8]

原則としてストローク確定までポーズを固定し、変更する場合はスナップショット世代を切り替える。旧世代の非同期ヒット結果を新世代へ適用しない。更新完了まで入力を待つか、直前のプレビュー状態を固定して整合を保つ。GPUとCPUで異なる変形結果を表示しない。任意シェーダーの頂点変位がBakeMeshで得られるとは仮定せず、対応アダプターまたは明示的な非対応表示が必要である。

## 3Dパスの編集契約

本要望の核は表面上の制御点をあとから変更できる筆跡である。PainterのPaint Along Pathは9.0で導入され、Filledは11.0、Ribbonは11.1の拡張である。FilledとRibbonを基本パスと混同せず、追加提案として扱う。Painterの既存パスは3D表面を対象とし、本拡張の2Dパス対応は独自の追加検討とする。[A1][A2][A3][A4]

| 項目 | 保存と編集の仕様案 |
| --- | --- |
| 制御点 | Binding ID、三角形ID、重心座標、表面からのoffset、接線方向、圧力、幅、必要な姿勢 |
| 補間 | 表面へ投影しながら点列を再生成。鋭角、穴、自己交差、反対面への飛び移りを検出 |
| 描画属性 | ブラシIDと版、間隔、乱数シード、チャンネル値、幅カーブ、始終端、更新範囲 |
| 編集操作 | 追加、削除、移動、接線調整、閉じる、複製、対称化、局所再生成、Undo |
| 拡張案 | Filledは閉曲線の内側判定と表面領域、Ribbonは幅と方向を持つ帯を別途設計 |

## モデル変更と再結合

参照モデルのトポロジー、UV、頂点順、サブメッシュ、骨構成が変わったら指紋で検出する。三角形IDの一致だけで自動継続しない。近傍位置、法線、UV、材質による候補は提示できるが、曖昧な再結合を確定しない。旧モデルと旧ラスタ結果を保持し、再結合・旧版維持・ラスタ固定化から選ぶ。再結合の許容誤差と失敗表示を試験する。

# 14 色空間と合成の規則

## 色とデータを分離する

ColorとEmissionの色は表示プロファイルとsRGB変換を管理し、Roughness、Metallic、Height、Normal、マスクは非色情報として扱う。データマップへsRGB変換を掛けない。GPU形式のsRGB読書き、RenderTexture設定、書き出し設定、Unityインポート設定を1つのアダプター契約にする。

ラスタ正本は元のstraight alphaとbit深度を保ち、透明画素のRGBも失わない。RGBA16Fは16-bit整数を常に完全保持できるとは限らない。premultiplied alphaや高精度合成は派生キャッシュに限定し、保存・Undoの唯一の正本にしない。Native Paintの演算色空間は明示する。PSDの保存アルファ表現への変換は境界で行う。入力と出力に同じRTを読み書きする不定な経路を作らず、ping-pongを使う。重なるスタンプは順序を保ち、無秩序な並列書込をしない。[U4] 完全透明画素のRGB、低アルファ部、消しゴム、マスクとクリッピングで黒縁や色縁が出ないことを検証する。[P3]

## PSDの見た目の一致

PSDの合成すべてを線形空間で処理すれば正しい、とはしない。外部アプリの色設定、ブレンド方式、ビット深度、塗りと不透明度、グループ分離の違いが結果に影響する。PSD Compatibleでは対応プロファイルと演算順序を定義し、参照画像との誤差を測定する。ICCを保持するだけでは色変換を実装したことにならない。[P1]

| 演算 | 実装時に固定する条件 |
| --- | --- |
| 通常合成 | アルファ表現、色空間、丸め、グループ分離、マスクとクリップの適用順 |
| 特殊合成 | PSD blend key、チャンネル式、端点、負値／HDR、塗りと不透明度の差 |
| 法線合成 | 接空間の定義、法線の正規化、合成方式、Y方向とUnityへのエンコード |
| 高さから法線 | 高さ基準、強度、texel size、UVの歪み、島境界、paddingの適用順 |
| 調整レイヤー | 入力色空間、演算順、マスク、パラメータ範囲、ビット深度、外部互換 |

## 表示品質と保存精度

プレビューを低解像度にする場合は状態を画面に明示し、元の作業・保存解像度を変えない。表示用の低精度キャッシュが保存正本に置き換わる経路を作らない。調整やぼかしを低解像度で近似した場合は、確定結果との違いと更新中状態を区別する。

RGB 8-bitを中心に開始する案は入口を狭めるための技術順序であり、16-bit、32-bit、HDR、CMYK、Lab、特殊プロファイルの要望を対応済みと扱わない。対象範囲はPSD互換マトリクスのゲートで決める。

# 15 4K多層を支えるメモリ設計

4Kは4096×4096画素とする。全面に実体画素を持つレイヤーと、少量だけ描いたレイヤーは必要容量が大きく異なる。「何千レイヤーなら軽い」といった枚数だけの保証はしない。解像度、format、占有率、有効チャンネル、マスク、Undo、合成中間、モデルの合計を測る。

| 非圧縮1面 | 4Kの容量 | 用途と注意 |
| --- | --- | --- |
| R8 | 16 MiB | スカラー1ch。精度が足りる範囲に限定 |
| RGBA8 | 64 MiB | 色＋アルファなど。100枚全面なら約6.25 GiB |
| R16／R16F | 32 MiB | 16-bitのスカラー。整数と浮動小数の意味は異なる |
| RGBA16F | 128 MiB | 高精度合成候補。常時全レイヤーへの採用は避ける |
| mipmap全段 | 基底に約33％追加 | 2D正方形の完全チェーンの概算。アラインメント等は別途 |
| 256×256 RGBA8 tile | 256 KiB | border、索引、配列padding、管理情報を除いた画素容量 |

## 採用案はアプリケーション管理の疎タイル

透明タイルと一様色タイルは値だけを持ち、必要になった部分だけ実体を割り当てる。GPUは固定サイズのタイルプール／アトラス、CPUは退避タイル、ディスクは復旧とコールドキャッシュを担当する。128／256／512画素タイルを比較し、固定配列の過大確保を避ける。GPU sparse textureの存在を前提としない。PSDのラスターデータは必要に応じて展開・再タイル化する。codecにも行／タイルの展開予算とディスク退避を要求し、全PSDを一括展開するライブラリは低容量要件の阻害要因として評価する。

GPU常駐は、現在のストローク、表示中の合成、近傍の予測タイルを優先する。下位レイヤーの合成チェックポイントをキャッシュし、同じ結果を何度も全層合成しない。ただし広範囲の調整・ぼかしや下位レイヤー変更では再計算が増える。

## 予算を機器に適応させる

OS、Unity Editor、モデル、他アセットの消費を見込み、予算を変更可能にする。VRAM容量の申告値だけで上限まで確保しない。使用量の計測値、確保失敗、転送待ちを監視し、非表示タイルの退避、キャッシュ削減、明示した低解像度プレビューの順に対処する。保存精度は落とさない。

全面を塗った多数のレイヤーには実データ量相応のRAM・ディスクとI/O時間が必要である。圧縮率やGPU退避で無制限の軽さは作れない。容量の見積りと安全な中断・保存を、限界時の仕様として含める。

# 16 更新スケジューラと履歴

## 変更タイルの依存グラフ

各ノードはレイヤー／マスク／Filter／Generator／Anchor／調整／合成／チャンネル出力で、入力revisionと領域を持つ。ストロークでdirtyになったタイルを上位へ伝播し、表示に必要な出力から優先処理する。ぼかしなどはカーネルのhalo、クリッピングは基底アルファ、グループは子構造への依存を持つ。全画面依存の演算は局所処理可能と偽らない。

入力キューはブラシの時刻と順序を保持する。表示は不要な中間フレームを省けても、最終画素を変えるスタンプは勝手に捨てない。遅延が増えたときは待ち行列、合成中、保存中を区別して表示し、取消し可能な処理単位を設ける。Jobは実行中に任意中断できると仮定せず、短いバッチと世代IDで無効結果を捨てる。使用中のNative配列を先に解放しない。Scheduleはメインスレッドで行い、結果が必要な時だけCompleteする。1スタンプごとのJob化や即時待機は避ける。レイヤー一覧は可視行を再利用し、非表示行まで毎フレーム作り直さない。[U6][U6a]

## UndoとRedo

画素の履歴は独自管理とし、変更タイルのbefore／after差分、必要な圧縮、構造操作、パラメータ変更を記録する。ストロークごとに全4Kテクスチャや全レイヤーの複製を取らない。操作再生だけに依存するとブラシ版や浮動小数差で結果が変わるため、復元に必要な確定差分を保持する。

Unity Undoはプレビュー設定など少量のUnity Objectメタデータと必要な明示操作に限定し、巨大な画素履歴を登録しない。1操作が画素と構造を変える場合は共通トランザクションIDで整合させる。履歴予算と復旧用スナップショットの予算は別にする。

## 読戻しと保存

毎ストロークの全テクスチャGPU読戻しはしない。CPU正本が必要な変更タイルだけをまとめて非同期転送し、GPU版とCPU版のrevisionを追跡する。保存スナップショットは必要な転送の完了を待ち、別世代のタイルを混在させない。同時要求数と一時バイト数を制限し、hasErrorと結果の寿命を管理する。非同期化しても転送量や待ち時間が消えるわけではない。[U7]

## 資源寿命と復旧

ウィンドウ終了、アセット再読込、Play Mode切替、Assembly Reload、OS終了に備える。購読イベント、Job、NativeArray、RT、ComputeBuffer、読戻しコールバックの所有者と解放順を統一する。正常終了時に確定していない処理を残さず、突然の停止には最後に耐久保存されたジャーナルとスナップショットまで復旧する。RT内容の消失も検出して再構築する。正常な再読込でも処理の排出による短い待ちはあり得る。[U9]

使い捨てのプレビューPNGを無制限に生成しない。復旧とキャッシュには保存先、容量上限、保持世代、掃除規則を定義する。ユーザーが編集中の世代や最後の正常保存は掃除対象にしない。

# 17 性能試験と暫定目標

以下は設計の評価目標であり、実測値・保証値・最低動作要件ではない。低スペックでの使いやすさを独立した合否軸にする。Unity本体、OS、ドライバー、モデル、他のEditor拡張を含む総使用量を記録する。

| 参考試験階層 | 構成例 | 評価の目的 |
| --- | --- | --- |
| 低容量 | RAM 16 GB／VRAM 4 GB または共有GPU | 任意の下位試験例。メモリ圧迫時も描画と保存を継続。これ未満を非対応と決定しない |
| 中容量 | RAM 32 GB／VRAM 8 GB | 4Kの日常作業と多数レイヤーの代表的な試験条件 |
| 高容量 | RAM 64 GB／VRAM 16 GB | 高密度データ、複数材質、余裕を活かした高品質表示を評価 |

| 指標 | 暫定目標と測定方法 |
| --- | --- |
| 入力から最初の表示 | 下記基準ケースで、中容量p95 50 ms以下、低容量p95 80 ms以下を初期上限目安とする。超える場合は設計を見直す。入力時刻と表示フレームを同時計測。CPU処理時間だけで代用しない |
| 描画中の表示 | 下記基準ケースで中容量60 fps、低容量30 fpsを目安。16.7 ms／33.3 msのフレーム予算と、入力から表示までの遅延を分ける |
| 重い合成の収束 | 即時フィードバックと最終品質の収束時間を別記録。全面調整や大きい混色は別ワークロードにする |

| 保存と復旧 | 保存所要時間、ピークRAM、ディスク使用、作業継続可否、強制停止後の最大データ損失範囲を計測 |

基準ケースは4K Color 1ch、100レイヤー各10％占有、全面フィルターなし、半径64 texel・直径の10％間隔の通常ブラシ、10万三角形の静的モデル、1920×1080相当の表示領域とする。50／80 msは最終的な描き心地の許容値ではない。軽い作業ではさらに低遅延を目指し、同一ペンタブでCSPと比較して官能評価する。

## レイヤー数以外を揃えたワークロード

4K単一Texture Setで20／100／500レイヤー、占有率1／10／100％、有効チャンネル1／3／6を組み合わせる。全組合せを同一性能目標にしない。空レイヤー、少数タイル、多層全面、深いグループ、調整、広いぼかし、Generator、Anchorの依存深度、ベイク、長い履歴、複数材質を分離して傾向を測る。

高負荷試験は時間だけでなく、予算内で開けるか、無言の品質低下がないか、保存できるかを判定する。ベンチマークにはモデル三角形数、skinning、BlendShape、描画領域、筆先間隔、画面サイズ、Graphics APIを含め、再現できるデータセットと操作列を固定する。

## 互換画像の評価方法

通常ラスタの無変更往復は画素一致を原則とし、意味上保持すべきメタデータの一致も確認する。合成はチャンネルごとの最大誤差と平均誤差、アルファ差、差分画像を残す。色差評価は比較色空間を固定する。普遍的な閾値を先に断定せず、8-bit、16-bit、各演算ごとに許容値を確定する。

## 停止と縮退

- GPU機能とformatのsampling／render／blend／random write／readback用途は起動時に個別診断する。[U11] 可能なCPU／ラスタ代替を選び、非対応機能を正直に表示する。画素を失う継続はしない。
- メモリ確保失敗は直近正常状態へ戻し、キャッシュ退避・保存・操作取消しを提示する。OS全体を圧迫する無制限リトライをしない。
- PSDの保持／再描画が安全でない場合は上書きを止め、原本維持と別名出力の選択を提示する。
- 復旧不能な入力やモデル変更は文書を破壊せず、最後の有効なラスタ結果と関連ソースを保存して診断する。
